Source repository: [Calendar](https://github.com/despia-legacy/calendar).

A Despia V3 extension over iOS EventKit and the Android Calendar Provider. Shared routes cover event and calendar reads, writes, recurrence, alarms, permission state and native editor presentation. Named platform routes expose iOS Reminders and Android provider tables when there is no shared operation.

```bash
npx despia-extensions add calendar
```

<Warning>
  Uploading files does not change an installed app. Rebuild the native app after you install, update or remove this extension. You own and maintain the extension's code once it is in your app.
</Warning>

## Install

Run the command above in your web project, commit, deploy, then rebuild the app. See [Install with the CLI](/extensions/install).

This extension has no settings.

## Call from the page

Install the SDK with `npm install despia-native`. Import `despia` from `despia-native` and watch the exact declared output variable. Call these functions from browser events:

```javascript
import despia from 'despia-native';

async function requestCalendarAccess() {
  const reply = await despia('extension://calendar/permissions?request=true&access=full', ['calendarPermissionsResult']);
  const answer = reply.calendarPermissionsResult;
  if (answer === undefined) { console.error('No native reply within 30 seconds'); return; }
  if (!answer.ok) { console.error(answer.code, answer.error); return; }
  return answer.data;
}

// After the system permission request finishes, read the actual state.
async function readCalendarAccess() {
  const reply = await despia('extension://calendar/permissions', ['calendarPermissionsResult']);
  const answer = reply.calendarPermissionsResult;
  if (answer === undefined) { console.error('No native reply within 30 seconds'); return; }
  if (!answer.ok) { console.error(answer.code, answer.error); return; }
  return answer.data;
}

// Read calendars after the permission result indicates access.
async function readCalendars() {
  const reply = await despia('extension://calendar/calendars', ['calendarCalendarsResult']);
  const answer = reply.calendarCalendarsResult;
  if (answer === undefined) { console.error('No native reply within 30 seconds'); return; }
  if (!answer.ok) { console.error(answer.code, answer.error); return; }
  return answer.data;
}

async function saveAppointment(selectedCalendarId) {
  const appointment = {
    calendar_id: selectedCalendarId, title: 'Example appointment',
    start_ms: Date.now() + 3600000, end_ms: Date.now() + 7200000,
    timezone: 'Europe/Paris', alarms: [{minutes: 15}]
  };
  const reply = await despia('extension://calendar/event_save?data=' + encodeURIComponent(JSON.stringify(appointment)), ['calendarEventSaveResult']);
  const answer = reply.calendarEventSaveResult;
  if (answer === undefined) { console.error('No native reply within 30 seconds'); return; }
  if (!answer.ok) { console.error(answer.code, answer.error); return; }
  return answer.data;
}
```

The permission request may answer with pending state before the system dialog finishes. Read `permissions` again or handle `onCalendarPermission` before making dependent calls. The extension also calls `onCalendarChanged`, a signal to refresh, and `onCalendarEditor`, which reports the native editor result. Register event handlers with browser lifecycle cleanup as described in [Calling a route](/extensions/reference/manifest#calling-a-route-with-the-despia-js-sdk).

Default outputs are `calendar<Route>Result` and `onCalendar<Route>Result`, with the route converted to PascalCase and underscores removed. For example, event_save returns calendarEventSaveResult through onCalendarEventSaveResult. IDs are opaque strings, not portable identifiers between platforms or accounts. Dates use Unix milliseconds. The route's data parameter is a JSON object encoded into a string of at most 4096 characters.

## Shared routes

| Route | Parameters | Answer variable | Successful data |
| --- | --- | --- | --- |
| capabilities | None | `calendarCapabilitiesResult` | Provider and supported feature booleans |
| permissions | Optional request boolean, access full, write_only or reminders | `calendarPermissionsResult` | Current permission state. A request is acknowledged promptly, then permission event reports the answer. |
| calendars | Optional entity events or reminders, default events | `calendarCalendarsResult` | Calendar rows with common id, title and writable fields. Android also returns raw provider fields under android. Reminders entity is iOS only. |
| calendar_save | data object with title, optional id; optional entity | `calendarCalendarSaveResult` | Saved calendar id and native metadata where available. New iOS calendars may need source_id. New Android calendars use a local account. |
| calendar_delete | id, optional entity | `calendarCalendarDeleteResult` | deleted: true |
| events | start_ms and end_ms required; optional calendar_id, offset, limit 1..100 | `calendarEventsResult` | Event occurrences, next_offset, has_more |
| event_get | id | `calendarEventGetResult` | Event fields, with platform metadata |
| event_save | data object; optional span this or future; optional occurrence_ms | `calendarEventSaveResult` | id, saved: true; Android also series_id with occurrence_ms (this) or split_ms (future) for a recurring event |
| event_delete | id; optional span this or future; optional occurrence_ms | `calendarEventDeleteResult` | deleted: true |
| present | Optional id, data and mode view, edit or create | `calendarPresentResult` | presented: true, which does not mean saved |

Event data supports id, calendar_id, title, start_ms, end_ms, all_day, timezone, location, notes and alarms. iOS also supports url. New Android events require calendar_id. An update preserves fields not supplied. EventKit requires a writable calendar. Android providers enforce their account and calendar rules.

Alarm writes use `{minutes: 15}` for a reminder 15 minutes before the event. iOS reads return minutes for time-only relative alarms, alongside offset_seconds. Native iOS triggers use an ios object: absolute_ms for an absolute date, structured_location with title, latitude, longitude and radius for a location, and proximity for the native EventKit proximity value. Location alarms can also include offset_seconds. These native fields are available for event and reminder alarm writes. Android event_get returns native reminder rows; the shared Android save route accepts nonnegative minutes before the event.

Recurrence writes use an array of objects with frequency 0 daily, 1 weekly, 2 monthly or 3 yearly, a positive interval, optional end_count or end_ms, days_of_week objects with day 1 Sunday through 7 Saturday and optional week ordinal, and optional days_of_month, months_of_year, weeks_of_year, days_of_year and set_positions. iOS accepts EventKit recurrence rules. Android accepts one RRULE through the shared writer and returns raw RRULE/RDATE/EXRULE/EXDATE under android metadata. For a recurring Android save, include start_ms and end_ms so duration can be formed.

For a recurring event, span this (the default) changes or deletes one occurrence, and span future that occurrence and every later one. occurrence_ms names the occurrence by its start in Unix milliseconds, as events returns it in start_ms; without it the span acts from the first occurrence, so a future delete without occurrence_ms deletes the whole series. An occurrence_ms that is not an occurrence of the event answers not_found. iOS uses EventKit's this-event and future-event spans. Android writes the same result through the Calendar Provider in one atomic batch: this inserts an exception (a changed or cancelled occurrence) for a series a sync account owns; the provider matches exceptions to their series by sync ID, so for a local calendar this adds the occurrence to the series EXDATE and, for a save, writes the changed occurrence as its own event, returned as id with the series as series_id. future ends the series before the occurrence with an RRULE UNTIL and, for a save, starts a new series there carrying the changes, the remaining COUNT and the alarms; the new series has its own id, returned as id with the old one as series_id.

## Platform methods and native UI

| Route | Answer variable |
| --- | --- |
| `android_table` | `calendarAndroidTableResult` |
| `ios_reminder_delete` | `calendarIosReminderDeleteResult` |
| `ios_reminder_save` | `calendarIosReminderSaveResult` |
| `ios_reminders` | `calendarIosRemindersResult` |
| `ios_sources` | `calendarIosSourcesResult` |

- ios_sources lists EventKit sources after event or reminders access is granted.
- ios_reminders lists reminder records, optionally filtered by calendar_id and completed, with offset/limit pagination.
- ios_reminder_save accepts a data object with id for updates, calendar_id, title, notes, location, url, priority, completed, start_ms, due_ms, completed_ms, timezone, alarms and recurrence. The device calendar interprets date components. ios_reminder_delete deletes by id. Android returns unsupported for these routes: Calendar Provider reminders are event alarms, not task lists.
- android_table exposes query, insert, update and delete for events, calendars, attendees and reminders, plus read-only instances. Query supports optional id or event_id where appropriate, offset/limit, and start_ms/end_ms for instances. Writes use data with native provider column names and scalar values. Update/delete require a specific id. Sync-adapter-owned fields are not writable through this ordinary-app API. iOS returns unsupported.
- present uses EventKit UI on iOS and installed calendar app intents on Android. iOS 17 can present a create editor without full calendar access; older iOS requires access. Reading an existing event requires full access. The iOS editor event reports saved, deleted, canceled or dismissed. Out-of-process editing does not provide an authoritative saved event payload. Android only acknowledges the handoff and does not claim a saved result; it can return unavailable if no calendar app handles the intent.

No adapter can grant permissions itself. A system dialog may remain open longer than a route deadline, so permission completion is an event and state remains queryable. Activity recreation uses the same namespaced Android Activity Result Registry key. After the app process dies, query state again rather than relying on a past event. changed is a signal to refresh, not a durable change journal. Read results in small pages; provider data and long notes may exceed bridge output limits.

## Platform limits

Current V3 iOS target is 16.6 and later. Android module minSdk24 and compileSdk36. Providers can reject read-only calendars, remote account writes or unsupported columns. iOS attendee fields are read-only in this adapter. Platform-only routes do not promise that every OS SDK method is already wrapped; the source is supplied so developers can add methods their app requires.
