title: "Install with the CLI"
description: "Install, configure, update and remove extensions in your web project with one command."
icon: "download"
---

```bash
npx despia-extensions add meta-ads --set appId=1234567890123456 --set clientToken=<client token>
```

Run it in your web project's root. It:

1. fetches the extension at the version this CLI release pins, and checks its files against a recorded hash;
2. copies it into `public/despia/<id>/` (`static/` for SvelteKit);
3. adds the id to `public/despia/extensions.json`;
4. writes your values where the native code reads them;
5. checks the result the way the build does.

Then commit the changed files, deploy your web app, and start a native rebuild.

<Warning>
  Uploading files does not change an installed app. Only a native rebuild does. Do not call a new route before the rebuilt app is installed.
</Warning>

## Find an extension

```bash
npx despia-extensions list --available     # what you can install
npx despia-extensions info meta-ads        # settings, server secrets, routes, permissions, SDK pins, docs link
```

## Values

Extensions that talk to a vendor need your keys. Pass them with `--set`, a file, or the environment:

```bash
npx despia-extensions add supabase --set url=https://abcdefghijklmnop.supabase.co --set publishableKey=sb_publishable_xxxxxxxx
npx despia-extensions add supabase --values despia-values.json
DESPIA_EXT_SUPABASE_URL=https://abcdefghijklmnop.supabase.co npx despia-extensions add supabase --from-env
```

The environment variable name is `DESPIA_EXT_<ID>_<KEY>`, for example `DESPIA_EXT_METAADS_APP_ID`.

Forgot a value? The extension is still installed and reported as `needs_config`, with the exact settings missing. Set them later:

```bash
npx despia-extensions config set supabase.publishableKey=sb_publishable_xxxxxxxx
npx despia-extensions config get supabase           # values are shown by their last 4 characters
```

## Values ship in your app. Secrets never do.

Everything the CLI writes ends up in your public folder and inside the app, where anyone can read it. That is correct for the keys a vendor's app SDK is built to ship with, such as a Meta client token, a Superwall public key or a Supabase publishable key.

Server secrets never go in your app. The CLI refuses them with exit code 4 and names the server variable to keep them in:

```text
DX-S001 metaads.appSecret: metaads.appSecret is a server secret. It must never be in your app or in public/. Keep it in your own server's environment as META_APP_SECRET.
```

It also refuses any value that looks like a known secret (private keys, `sk_live_`, `sb_secret_`, service-role tokens, service-account JSON). If a value is public but trips that check, open it in words:

```bash
npx despia-extensions config set myext.token=<value> --public-value myext.token --confirm-public "this value ships in my app"
```

A setting the extension declares as a server secret can never be set, with or without that flag.

## Update, check, remove

```bash
npx despia-extensions update                 # every extension; shows what changes for your app first
npx despia-extensions update meta-ads --major  # a breaking version needs --major
npx despia-extensions doctor                 # values, files, secrets and the build's own validator
npx despia-extensions doctor --hosted https://app.example.com   # what your deployed site really serves
npx despia-extensions remove meta-ads
```

`remove` refuses an extension another installed extension requires and names it. See [Dependencies](/extensions/build/dependencies).

`update` lists routes added or removed, new permissions, purpose strings and entitlements, and SDK version changes before it writes anything. If you edited an installed file by hand, `update` stops (exit 5). Choose `--overwrite` to take the new file, or `--keep-mine` to keep your edit; the new file is then saved in `.despia/incoming/<id>/`.

`doctor --hosted` fetches your deployed files exactly as the build does: HTTPS on port 443, no redirects. It catches the most common hosting mistake, a single-page-app fallback that answers `/despia/extensions.json` with your HTML.

## Files the CLI keeps

```text
despia.extensions.json          what is installed and its public values   (commit it)
despia.extensions.lock.json     the source lock: exact source and hashes  (commit it)
.despia/extensions/<id>/        licence, policy, descriptor, upstream manifest (commit it)
.despia/backup/  .despia/incoming/   previous trees and kept edits (git-ignored)
public/despia/                  the served files: extensions.json + <id>/{manifest.json, ios/, android/}
```

After a merge or a fresh clone, restore the served files from the two committed files:

```bash
npx despia-extensions sync
```

Nothing of the CLI's own goes into `public/despia/`. The build refuses any file a manifest does not name.

## Your own and private extensions

```bash
npx despia-extensions add ./extensions/weather          # a folder in your repo
npx despia-extensions add github:your-org/weather#v1.2.0  # a GitHub repository at a tag, branch or commit
```

A private repository needs `GH_TOKEN` in the environment with read access to it. The CLI never stores the token. The installed source is served from your site, so it is public there even if the repository is private. See [Publishing and sharing](/extensions/build/publishing).

## For coding agents

- Every command takes `--json` and prints one object: `{"ok", "command", "changed", "extensions", "missing", "errors", "next"}`.
- No command ever prompts. `--dry-run` shows the same report and writes nothing.
- Exit codes: 0 ok, 2 usage, 3 check failed (including `needs_config`), 4 secret refused, 5 local edits would be overwritten, 6 network or registry. The full list is in the [CLI reference](/extensions/reference/cli#exit-codes).
- `add` without the values reports them in `missing`, so the agent asks you for exactly those, then runs `config set`.

See the [CLI reference](/extensions/reference/cli) and the [AI skills](/extensions/ai-skills).

## Install by hand

You can still copy an extension yourself: `manifest.json`, `ios/` and `android/` from its repository into `public/despia/<id>/`, add the id to `public/despia/extensions.json`, and replace each `REPLACE_...` placeholder with your value. The CLI does not manage a folder you copied by hand; the build checks it.
