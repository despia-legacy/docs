```bash
npx despia-extensions add recorder --set uploadHosts=uploads.example.com
```

That line installs the Background Recorder extension into your web project. Your next native rebuild compiles it into your app. Your web code then calls it:

```javascript
import despia from 'despia-native';

// Run from a click handler or a client lifecycle hook inside the installed app.
const reply = await despia('extension://recorder/status', ['recorderStatus']);
const answer = reply.recorderStatus;
if (answer === undefined) console.error('No native reply within 30 seconds');
else if (!answer.ok) console.error(answer.code, answer.error);
```

An extension is native Swift (iOS) and Kotlin or Java (Android) code, described by a JSON manifest. Your web app serves the files from its own HTTPS origin, a native rebuild compiles them in, and your page calls them with `extension://<id>/<route>`.

<Warning>
  **Native rebuild required.** Installing, updating or configuring an extension changes files your web app serves. An installed app keeps its old native code until a native rebuild includes the new files. Do not call a new route from your web app before the rebuilt app is installed.
</Warning>

## How it works

<Steps>
  <Step title="The manifest declares the extension">
    Each extension folder has a `manifest.json`. The folder name is the extension id. The manifest declares its routes, each route's typed parameters, its answer variable and callback, its events, and its native files.
  </Step>
  <Step title="Your web app serves the files">
    The files sit under `public/despia/` in your web project and are served from your app's own HTTPS origin. The CLI writes them for you.
  </Step>
  <Step title="A native rebuild compiles them in">
    The build fetches and verifies the index, every manifest, every named file and every pinned dependency, then compiles them into your app. A change to any of them needs a new native build. It cannot be sent over the air.
  </Step>
  <Step title="Your page calls a route and gets one answer">
    The runtime checks each call: the extension and route exist, only declared parameters are present, and each value has its declared type. Then your native handler runs, and the answer comes back once, on the route's answer variable.
  </Step>
</Steps>

## Call a route

```bash
npm install despia-native
```

```javascript
import despia from 'despia-native';

async function readRecording(id) {
  const command = 'extension://recorder/status?id=' + encodeURIComponent(id);
  const reply = await despia(command, ['recorderStatus']);
  const answer = reply.recorderStatus;
  if (answer === undefined) { console.error('No native reply within 30 seconds'); return; }
  if (!answer.ok) { console.error(answer.code, answer.error); return; }
  return answer.data;
}
```

- Watch the answer variable the manifest declares. `npx despia-extensions info <name>` lists them.
- Check both cases: `undefined` (no answer within 30 seconds) and `ok: false` (a native error). A native error does not reject the promise.
- Encode each value with `encodeURIComponent`, not the whole command.
- Await one call before the next when both watch the same variable.
- Call from a click handler or a mounted client hook. Server rendering must not run native calls.

The full rules (answer envelope, error codes, timeouts, events) are in the [manifest reference](/extensions/reference/manifest#calling-a-route-with-the-despia-js-sdk).

<Note>
  Calls are accepted only from the top-level page of your app's own HTTPS origin, or from origins you list in `bridge.allowed_origins`. Iframes, other origins, popups and page sheets get no answer.
</Note>

## Frameworks and app builders

The SDK works the same in React, Vue, Svelte, Next.js, TanStack and plain HTML. For Lovable, Base44, Replit or another builder, use a project that can run custom JavaScript and serve files at exact paths under `public/`. A browser preview has no native features; test in the installed app.
