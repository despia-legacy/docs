## How it Works

Storage Vault keeps small values where the user's account can carry them:

- **iPhone**: iCloud Key-Value Store. With the app's iCloud capability on and the user signed in to iCloud, values sync to the user's other devices on the same Apple ID and come back after a reinstall. Turn on iCloud for your App ID in Apple Developer: Despia's iOS build keeps the Key-Value Store entitlement only when your provisioning profile has iCloud. Without the iCloud capability the store is not available: `setvault://` and `readvault://` answer `store_unavailable` on `window.storageVault`. Without an iCloud account nothing comes back after a reinstall.
- **Android**: Android Auto Backup to the user's Google Drive. It is a backup, not a live sync: Android backs up at most once every 24 hours (backup on, device idle, on Wi-Fi), and a reinstall gets back only what the last backup held. The backup is end-to-end encrypted only on Android 9 or higher with a screen lock.

**Storage Vault is not encrypted by Despia.** Values are saved as plain text in the app's own storage. When `locked` is set to `true`, the user must pass Face ID, Touch ID or the passcode (iPhone) or any enrolled biometric (fingerprint or face, strong or weak class) or the device PIN, pattern or password (Android) before the value is handed to your page; the stored value itself is not encrypted by the lock. For login tokens and other secrets use Identity Vault (`identityvault://`), which uses the iOS Keychain and the Android Keystore.

`readvault://` never throws: a missing key, a cancelled prompt or a failed prompt all give `null`, and `window.storageVault` names which one: `{ op, key, ok, error: { code, message } }` with `not_found`, `store_unavailable` (iPhone app built without the iCloud capability), `auth_cancelled`, `auth_failed`, `lock_unavailable`, `storage_error` or `invalid_argument`. Each `setvault://` names its outcome there too, and `window.onStorageVaultResult` is called with it when you define it.

## Usage

### 1. Import the SDK

```javascript
import despia from 'despia-native';
```

### 2. Store Data

**Basic storage:**

```javascript
await despia(`setvault://?key=userId&value=user123&locked=false`);
```

**Protected with Face ID/fingerprint:**

```javascript
await despia(`setvault://?key=sessionToken&value=abc123&locked=true`);
```

### 3. Retrieve Data

**Read basic data:**

```javascript
const data = await despia(`readvault://?key=userId`, ['userId']);
const userId = data.userId;
console.log(userId); // "user123"
```

**Read Face ID protected data:**

```javascript
// User will see Face ID/fingerprint prompt
const data = await despia(`readvault://?key=sessionToken`, ['sessionToken']);
const token = data.sessionToken;
console.log(token); // "abc123" after Face ID success, null when cancelled or failed
```

### 4. Prevent Free Trial Abuse

```javascript
// Check if user has used trial before
async function checkIfNewUser() {
  const data = await despia(`readvault://?key=hasUsedTrial`, ['hasUsedTrial']);

  if (data.hasUsedTrial === 'yes') {
    console.log('User already used their trial');
    return false;
  }
  // null: no data found - a new user on this account or device
  console.log('New user, can start trial');
  await despia(`setvault://?key=hasUsedTrial&value=yes&locked=false`);
  return true;
}
```

### 5. Remember a Non-Secret Setting

Login tokens belong in Identity Vault (`identityvault://`), which encrypts them. Storage Vault suits small values that are fine unencrypted:

```javascript
// Save a setting
async function saveRegion(region) {
  await despia(`setvault://?key=preferredRegion&value=${encodeURIComponent(region)}&locked=false`);
}

// Read it when the app opens
async function loadRegion() {
  const data = await despia(`readvault://?key=preferredRegion`, ['preferredRegion']);
  return data.preferredRegion ?? 'default';
}
```

### 6. Protect Sensitive Actions with Face ID

```javascript
// User wants to delete their account
async function deleteAccountWithConfirmation() {
  // Store temporary confirmation key
  await despia(`setvault://?key=deleteConfirm&value=confirmed&locked=true`);
  
  // This triggers Face ID/fingerprint
  const data = await despia(`readvault://?key=deleteConfirm`, ['deleteConfirm']);

  if (data.deleteConfirm === 'confirmed') {
    // Face ID passed, delete account
    await deleteAccount();

    // Clear the confirmation key
    await despia(`setvault://?key=deleteConfirm&value=&locked=false`);
  } else {
    console.log('User cancelled or Face ID failed'); // the answer was null
  }
}
```

### 7. Track App Opens

```javascript
// Count how many times user opened the app
async function trackAppOpen() {
  const data = await despia(`readvault://?key=openCount`, ['openCount']);
  const count = parseInt(data.openCount || '0') + 1; // null on the first open

  await despia(`setvault://?key=openCount&value=${count}&locked=false`);

  if (count === 1) {
    console.log('First time opening app');
  } else {
    console.log(`App opened ${count} times`);
  }
}
```

### 8. Handle Errors

```javascript
async function readData(keyName) {
  const data = await despia(`readvault://?key=${keyName}`, [keyName]);
  return data[keyName]; // null when missing, cancelled or failed
}
```

### 9. Common Examples

**Remember device:**

```javascript
await despia(`setvault://?key=deviceId&value=device123&locked=false`);
```

**Save user settings:**

```javascript
await despia(`setvault://?key=darkMode&value=true&locked=false`);
```

**Protect with Face ID:**

```javascript
await despia(`setvault://?key=sensitiveAction&value=approved&locked=true`);
```

**Check first app launch:**

```javascript
const data = await despia(`readvault://?key=firstLaunch`, ['firstLaunch']);
if (data.firstLaunch === 'done') {
  console.log('User has opened app before');
} else {
  await despia(`setvault://?key=firstLaunch&value=done&locked=false`);
  console.log('First time user!');
}
```

## What to Store

### Good Uses

- User IDs and device IDs
- Free trial tracking (best effort)
- App preferences and settings
- First-time user flags
- Actions that need Face ID confirmation

### Don't Store

- Login session and refresh tokens (use Identity Vault)
- Passwords (use proper login systems)
- Credit card numbers (use payment processors)
- Private encryption keys
- Data that requires legal compliance (medical, financial records)

## Tips

1. **Keep it simple** - Store simple text values like IDs and tokens
2. **Use Face ID for important actions** - Set `locked=true` when you want user confirmation
3. **Reinstall depends on the user's account** - Values come back after a reinstall only through iCloud (iPhone) or the last Google backup (Android)
4. **Works offline** - No internet connection needed
5. **Follows the user** - iCloud syncs to the user's iPhone and iPad; Android restores from the Google backup on a reinstall or a new phone
