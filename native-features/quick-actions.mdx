When the user long-presses your app icon, the OS shows a list of shortcuts you configured for your app: Home Screen quick actions on iOS, app shortcuts in the launcher on Android. Tapping one launches your app, opens the shortcut's Quick Link, and runs the JavaScript you set on it, which can call a global function of yours. There is no SDK call from your code, the runtime runs the snippet directly.

---

## Installation

Quick Actions does not require installing the `despia-native` package. The runtime invokes your global function directly when the shortcut fires, no SDK calls or imports needed on your side. Install `despia-native` only if your page also uses other Despia schemes.

## How it works

Two pieces have to line up. First, attach the function you want the shortcut to trigger as a global on `window`. Second, configure a Quick Action that calls that function. The runtime picks up the configuration during the build and wires the shortcut to invoke your function on tap.

```javascript
window.dontLeave = function () {
    // your workflow here, runs when the user taps the shortcut
}
```

The function must be globally accessible because the native runtime invokes it by name. Defining it inside a closure or module scope will not work, the runtime cannot reach it.

---

## Configuring a shortcut

Each shortcut has four settings: a label, an icon, a Quick Link, and a JavaScript snippet that the runtime executes once the Quick Link has loaded. The shortcuts are compiled into the app, so a change needs a new build and cannot be applied over-the-air.

| Setting | What to set |
| --- | --- |
| Label | A short, action-oriented text like `Don't Leave`, `Track Macros` or `Scan Invoice`. It is the text the user sees in the long-press menu. |
| Icon | The icon shown next to the label in the long-press menu. |
| Quick Link | The page of your app that defines the function, for example your app's home address. The runtime opens it when the shortcut is tapped, and runs your JavaScript once that page has loaded. On Android a shortcut without a label or without a Quick Link is not published. |
| JavaScript | The snippet that calls your global function, for example `window.dontLeave()`. Replace `dontLeave` with the name you used for your global function in the web app. The name has to match exactly. |

Add one shortcut per action, each with its own label, icon, and function call. Each shortcut is independent.

<Warning>
  The function name in the shortcut's JavaScript must match the global function name in your web app exactly. A typo on either side means the shortcut taps into a `function is not defined` error and nothing happens. Copy the name, do not retype.
</Warning>

## Platform notes

| | iOS | Android |
| --- | --- | --- |
| Where it shows | Long-press menu of the Home Screen icon | App shortcuts of the launcher, on the app icon |
| How many | The first four, in the configured order | The first four, in the configured order, and never more than the launcher's own limit (`getMaxShortcutCountPerActivity`; most launchers show four) |
| Icon | The shortcut's symbol, as a system symbol | The same symbol drawn from its vector path as the shortcut icon; the app icon when it cannot be drawn |
| Published | When the app starts | On every launch, replacing the app's earlier shortcuts; an empty list clears them |
| On tap | Opens the Quick Link, then runs the JavaScript | Opens the Quick Link through the web view's normal link checks, then runs the JavaScript. On a cold start this happens once the first page has loaded |

On Android the shortcut carries only its position, never the link or the script. The app looks the shortcut up in its own list when it is tapped, so another app cannot send your web view a link or a script. A shortcut that is not in the list does nothing, and neither does a Quick Link that starts with `javascript:`, `file:`, `data:`, `content:`, `blob:` or `vbscript:`. A tap runs once: recreating the app or reopening it from Recents does not replay it. Source for the launcher limit: Android Developers, "App shortcuts" (shortcut limitations), read 25 Nov 2026.

## Define the global function

The function attaches to `window` directly. In a vanilla HTML page you can write `window.dontLeave = function() { ... }` at any point before the user could possibly tap the shortcut. In a React or other framework app, attach inside a top-level `useEffect` so the function lands on `window` once the app mounts and stays there for the rest of the session.

```jsx
import { useEffect } from 'react'

function App() {
    useEffect(() => {
        window.dontLeave = () => {
            showFeedbackModal()
        }

        window.trackMacros = () => {
            navigateTo('/macros/new')
        }

        window.scanInvoice = () => {
            startCameraScan()
        }
    }, [])

    return <YourApp />
}
```

Re-bind on every mount of your top-level component so the function survives navigation and component swaps. The native runtime fires the call whenever the user taps the shortcut, including on cold app launches, so the function has to be on `window` before any user interaction is possible.

## Pass arguments via the function body

The shortcut's JavaScript setting executes the snippet you put there as a literal expression, so you can pass hardcoded arguments to your function if one shortcut should always do one specific thing. This unlocks "one function, many shortcut variations" without defining a new global per shortcut.

```javascript
window.openCategory = function (category) {
    navigateTo(`/categories/${category}`)
}
```

In the JavaScript setting of each shortcut:

```javascript
window.openCategory('food')      // Shortcut 1: "Browse Food"
window.openCategory('drinks')    // Shortcut 2: "Browse Drinks"
window.openCategory('desserts')  // Shortcut 3: "Browse Desserts"
```

Three shortcuts, one function. Each shortcut shows up separately in the long-press menu.
