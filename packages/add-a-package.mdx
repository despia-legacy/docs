<Info>Requires Despia version 4 or greater.</Info>

A package is a native feature your web app can call, such as payments, push notifications or sign-in. Your app only contains the packages you add. Once a package is added and the app is rebuilt, it answers on `window.dsx.module.<package>` (see [Modern API](/packages/overview)).

There are three ways to add one. They all change the same project, so pick whichever fits how you work.

## In the console

<Steps>
  <Step title="Open your app">
    In the sidebar, click **Apps**, then open the app.
  </Step>
  <Step title="Open its packages">
    Click **Packages**. You see what is **In this app** and what is **Always Included**.
  </Step>
  <Step title="Pick a package">
    Click **Add Packages**. The **Add packages** sheet opens. Search, or filter by **Category**, then click **Add** on the package you want.
  </Step>
  <Step title="Confirm">
    The confirm sheet shows **What It Adds**, what **The System Asks For** (the permissions it needs), and what **You Will Set** (its settings, such as an API key). Fill in the settings and click **Add**.
  </Step>
  <Step title="Build">
    The package is added to the app at its next build. Start a new build from **Builds**.
  </Step>
</Steps>

To browse every package before choosing an app, click **Packages** in the workspace section of the sidebar. To change a package's settings later, open it from the app's **Packages** page and click **Configure**. **Remove from This App** takes it out again.

## With the CLI

The CLI is the npm package `@despia-native/cli`. Inside a project, run it with `npx despia`, or install it globally with `npm install -g @despia-native/cli`.

<Steps>
  <Step title="Find the package">
    ```bash
    npx despia search camera
    ```
    This searches the built-in index of first-party packages and works offline.
  </Step>
  <Step title="Preview the change">
    ```bash
    npx despia add revenuecat --plan
    ```
    `--plan` prints exactly what would change and writes nothing.
  </Step>
  <Step title="Add it">
    ```bash
    npx despia add revenuecat
    ```
    A first-party package is added to the `modules` list in your project's `dsx.config.json`, together with the packages it depends on.
  </Step>
  <Step title="Check what is in the app">
    ```bash
    npx despia packages
    ```
  </Step>
</Steps>

`npx despia remove <package>` takes a package out again (also with `--plan`). If you pass a capability instead of a package name, for example `npx despia add analytics`, nothing is written: the CLI lists the packages that provide that capability so you can choose one. A typo gets a "Did you mean" suggestion.

<Note>
  Starting from a website? `npx despia new --web https://your-site.com` checks everything and writes nothing; add `--apply` to create the app. Web App to Mobile App is the template offered in 0.1.0.
</Note>

## With the MCP server

The CLI also runs as an MCP server, so an AI coding agent (Claude Code, Cursor and others) can add packages for you. Set it up as described in [Despia MCP](/packages/mcp), then ask:

> Add the RevenueCat package to this app. Show me the plan first.

The agent uses the `despia_search`, `despia_add` and `despia_packages` tools. It can preview and add first-party packages; anything that leaves your project, such as accepting an unreviewed community package, is refused over MCP and handed back to you as a command to run yourself.
