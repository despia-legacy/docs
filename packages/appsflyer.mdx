Starts the AppsFlyer SDK at launch, logs in-app events and ad revenue, reports where an install came from and resolves OneLink deep links into your app. Does nothing until a dev key is set. Needs an AppsFlyer account, your dev key and, on iOS, your Apple app ID.

**When to use it.** Use it when you buy ads and need to know which campaign produced an install or a purchase. It does nothing until you set your AppsFlyer dev key.

<EnvNew />

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `appsflyer` package is on the global `window.dsx`. `dsx.has('appsflyer')` is true when the package is in your app's build:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('appsflyer')) {
  // Records an in-app event, such as a purchase or sign-up, so AppsFlyer can credit it to the campaign that brought the user.
  const logEvent = await dsx.module.appsflyer.logEvent({ event_name: "purchase", event_values: {"value": 9.99} })

  // Tells AppsFlyer your own id for the signed-in person so their events are tied together across devices.
  const setUserId = await dsx.module.appsflyer.setUserId({ customer_user_id: "u_12345" })

  // Returns the AppsFlyer id of this install, which you can send to your server to match it with AppsFlyer reports.
  const getUid = await dsx.module.appsflyer.get_uid()
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

## Action reference

<AccordionGroup>
<Accordion title="get_attribution">

Returns where this install came from: the ad network, campaign, ad and deep link details AppsFlyer recorded.

**Arguments:** none.

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.appsflyer.get_attribution()
```

```json Result
{
  "attribution": {
    "is_organic": true,
    "media_source": "organic"
  }
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `attribution` | object | The attribution record. Fields AppsFlyer did not report are missing. |

**Errors**

| Code | Message |
| :-- | :-- |
| `not_configured` | AppsFlyer is not running in this build, set config.dev_key, or install the PBA tag on the web. |
| `sdk_error` | The AppsFlyer SDK refused the call. |
| `unsupported_platform` | AppsFlyer's browser product exposes no such call. |

</Accordion>

<Accordion title="install">

Gives the growth package this install's attribution as a normalised record, or nothing for organic installs.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `token`? | string | Ignored. It exists only so the growth package can call every attribution source the same way. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.appsflyer.install()
```

```json Result
{
  "method": "deterministic",
  "referrer": "tiktokglobal_int",
  "source": "appsflyer"
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `adGroup`? | string | The ad set that referred the install. |
| `campaign`? | string | The campaign that referred the install. |
| `creative`? | string | The ad that referred the install. |
| `method` | string | How the install was matched, always deterministic. |
| `referrer`? | string | The media source that referred the install. |
| `source` | string | The attribution source, always appsflyer. |

</Accordion>

## Broadcasts

Listen with `window.dsx.module.appsflyer.on('<broadcast>', (data) => { ... })`. It returns a function that stops listening.

| Broadcast | When it fires |
| :-- | :-- |
| `deepLink` | Fires when a OneLink or deferred deep link opens the app, or when an install is attributed. |

## Configuration

Set these in the package settings of your app (see [Add a package](/packages/add-a-package)).

| Setting | What it is |
| :-- | :-- |
| Apple app ID (`apple_app_id`) | The app's numeric App Store ID used by AppsFlyer. |
| Debug mode (`debug_mode`) | Verbose AppsFlyer SDK logging for integration testing. |
| Dev key (`dev_key`) | Your AppsFlyer developer key from the AppsFlyer dashboard. |
| OneLink domains (`onelink_domains`) | Your OneLink domains, so those links go to AppsFlyer instead of opening in the app. |

## What you need on your side

- An AppsFlyer account: the **dev key** and your **Apple app id** in the package settings.

Despia never hosts your app, your backend or your users' content: the accounts and servers above are your own.

For apps built on Despia V3, see [Migrate from Despia V3](/packages/migrate-from-v3).
