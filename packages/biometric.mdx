Shows the system prompt so the user can confirm it is them with biometrics, falling back to the device passcode. Without a challenge the answer is a yes or no for the interface (a modified client can fake it, so it never protects data); pass a server challenge and the answer is a passkey assertion your server verifies. To keep a secret behind biometrics use the vault's locked records. You write the reason text shown in the prompt.

**When to use it.** Use it to confirm the person holding the phone before showing a screen or acting on a tap. For anything that protects data or money, pass a server challenge so your server can verify the answer.

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `biometric` package is on the global `window.dsx`. `dsx.has('biometric')` is true when the package is in your app's build:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('biometric')) {
  // Shows the system Face ID, Touch ID or fingerprint prompt, falling back to the device passcode, and tells you whether the person confirmed.
  const authenticate = await dsx.module.biometric.authenticate({ reason: "Unlock your records" })
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

## Action reference

<AccordionGroup>
<Accordion title="authenticate">

Shows the system Face ID, Touch ID or fingerprint prompt, falling back to the device passcode, and tells you whether the person confirmed.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `allow`? | string[] | A list of credential ids that may answer the challenge. Used only together with challenge. |
| `challenge`? | string | A one-time value from your server; when given, the answer is a passkey assertion your server can verify. |
| `reason`? | string | The sentence shown in the prompt, for example Unlock your vault; defaults to the usage description in the package config. |
| `rpId`? | string | The domain of your server (the relying party) that the passkey belongs to. Used together with challenge. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.biometric.authenticate({ reason: "Unlock your records" })
```

```json Result
{
  "ok": true
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `assertion`? | object | The signed passkey proof your server verifies. Present only when a challenge was given and ok is true. |
| `message`? | string | A readable explanation of the failure from the system. |
| `ok` | boolean | True when the person confirmed, false when they did not or the device could not ask. |
| `platformCode`? | number | The operating system's own error number, useful only for diagnosis. |
| `reason`? | string | Why it failed when ok is false, such as cancelled, fallback, failed, lockout or not_enrolled. |

**Errors**

| Code | Message |
| :-- | :-- |
| `busy` | The authenticator is in use. Try again in a moment. |
| `challenge_unsupported` | A challenge needs Core/Passkeys in the build: it performs the server-verifiable ceremony. |
| `failed` | The passkey confirmation could not run. |
| `not_set_up` | Biometric unlock isn't set up on this device. |
| `unsupported_device` | This device has no authenticator to ask: no biometric or device-credential hardware route (on the web, a browser with no WebAuthn over HTTPS). |

</Accordion>
</AccordionGroup>

## Configuration

Set these in the package settings of your app (see [Add a package](/packages/add-a-package)).

| Setting | What it is |
| :-- | :-- |
| Permission prompt (`usage_description`) | The message explaining why the app uses Face ID / Touch ID. |
