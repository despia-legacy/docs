## Listen to a broadcast

Packages also send broadcasts that are not the answer to a call, for example when a purchase changes the customer's entitlements. Listen on the package:

```javascript
const off = window.dsx?.module.revenuecat.on('customerInfo', (data) => { /* ... */ })
off?.()  // stop listening
```

A package declares its broadcasts under `broadcasts` in its `dsx.json`; each package page lists them with their payload.

- `dsx.module.<package>.on('<broadcast>', (data) => {})` receives one broadcast and its payload.
- `dsx.module.<package>.on((envelope) => {})` and `dsx.on('<package>', (envelope) => {})` receive every broadcast of the package as the whole envelope `{ event, data, scheme, ... }`, where `event` is the broadcast's name.
- Each returns a function that stops listening.

## Failures are rejections, not broadcasts

When a call fails, its promise rejects with a typed error that carries a `code`. There is no error broadcast to listen for. For example, `fileviewer.preview()` rejects with `invalid_src`, `download_failed` or `write_failed`:

```javascript
try {
  await window.dsx.module.fileviewer.preview({ src: 'https://example.com/report.pdf' })
} catch (err) {
  if (err.code === 'download_failed') showRetry()
}
```

Despia V3 callbacks that only answered a call (`onBioAuthSuccess`, `onOneSignalLogin`, the `despiafileerror` event, `offeringsData`) have no broadcast: their Despia V4 form is the call's result or its rejection. See each package page for the codes.

## Despia V3 pages keep hearing the old events

The Legacy polyfill listens to the Despia V4 broadcasts and fires the Despia V3 event or callback with the Despia V3 payload, so an existing page needs no change. For example, the `focus.change` broadcast with `focused: false` calls `window.focusout()`, `admob.earned` calls `updateRewardedStatus('true')`, and on iOS a `fileviewer.preview` rejection still dispatches the `despiafileerror` event (`{ reason, url, message }`).
