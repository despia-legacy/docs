Uses Clerk's native sign-in and sign-up views, email codes and social logins, and returns a session token for your own API calls. Use it if your users already live in Clerk. Needs a Clerk account and your publishable key.

**When to use it.** Add it when your people already have Clerk accounts or you want Clerk's sign-in, social logins, passkeys, organizations and prebuilt screens. If you do not use Clerk, use the Auth package instead.

<EnvNew />

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `clerk` package is on the global `window.dsx`. `dsx.has('clerk')` is true when the package is in your app's build:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('clerk')) {
  // Reads who is signed in, working offline from what the device already holds.
  const statusResult = await dsx.module.clerk.status()

  // Gives Clerk your publishable key so sign-in can start.
  const configure = await dsx.module.clerk.configure({ key: "pk_test_abc123" })

  // Shows Clerk's prebuilt sign-in and sign-up sheet and waits until it closes.
  const authview = await dsx.module.clerk.authview({ mode: "signup" })
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

## Broadcasts

Listen with `window.dsx.module.clerk.on('<broadcast>', (data) => { ... })`. It returns a function that stops listening.

| Broadcast | When it fires |
| :-- | :-- |
| `authChanged` | The signed-in state changed: a sign-in, a sign-out, or a session token rotation. It never carries the token: call token() for it. |

## Configuration

Set these in the package settings of your app (see [Add a package](/packages/add-a-package)).

| Setting | What it is |
| :-- | :-- |
| Publishable key (`publishable_key`) | Your Clerk publishable key (pk_test_... or pk_live_...). Leave it empty to configure Clerk at run time with configure(). |

## What you need on your side

- A Clerk application and its **publishable key** (`pk_test_...` or `pk_live_...`) in the package settings.
- Your backend verifies the session token from `clerk.token()` with Clerk before it trusts a request.

Despia never hosts your app, your backend or your users' content: the accounts and servers above are your own.

For apps built on Despia V3, see [Migrate from Despia V3](/packages/migrate-from-v3).
