Opens the share sheet with a file attached, so the user can send it to Messages, Mail, AirDrop, Drive, Files or any app that accepts shared files. You can share a file that is already on the device, or give an https address and the package downloads it first. Links that the server marks as attachments are shared automatically. You write the button or link that asks for the share.

**When to use it.** Use it when the user should send, save or open a file in another app, such as a report, a ticket or an exported image. If you only want to show a link or a short text, a normal web share is enough.

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `filesharing` package is on the global `window.dsx`. `dsx.has('filesharing')` is true when the package is in your app's build:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('filesharing')) {
  // Opens the system share sheet with a file, taken from a device path or downloaded first from an https address.
  const shareResult = await dsx.module.filesharing.share({ url: "https://files.example.com/report.pdf" })
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

| Call | Arguments | Returns | Platforms | What it does |
| :-- | :-- | :-- | :-- | :-- |

## Action reference

<AccordionGroup>
<Accordion title="share">

Opens the system share sheet with a file, taken from a device path or downloaded first from an https address.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `filename`? | string | The name to give the shared file; if left out, the name from the path or address is used. |
| `path`? | string | A path to a file already on the device, such as cache: or documents:; give this or url. |
| `url`? | string | An https address of the file to download and share; give this or path, not both. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.filesharing.share({ url: "https://files.example.com/report.pdf" })
```

```json Result
{
  "delivery": "share_sheet",
  "shared": true
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `cancelled`? | boolean | True only when the user closed the share sheet without choosing. |
| `delivery` | "share_sheet" \\| "download" | How the file reached the user: share_sheet, or download in a browser that cannot share files. |
| `path`? | string | The device path that was shared; it is only returned when you passed a path. |
| `shared` | boolean | True when the user picked a destination, false when they closed the sheet. |

**Errors**

| Code | Message |
| :-- | :-- |
| `download_failed` | Could not download the file. Check the connection and try again. |
| `download_too_large` | The file exceeds the 64 MB native download limit. |
| `invalid_url` | Only valid HTTPS download URLs are allowed. |
| `missing_param` | Pass the file as `path` (a Core/Files path) or `url`. |
| `no_presenter` | Could not find a screen to share from. |
| `not_found` | There is no file at that path. |
| `share_failed` | The share could not be completed. |
| `unsupported_platform` | This browser cannot hand a file to the user. |
| `write_failed` | Could not save the file. |
