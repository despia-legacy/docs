When a person taps a file input, the app shows the native source sheet and hands the chosen files back to your page as a normal file selection. Your existing upload code keeps working unchanged. The accept and capture attributes choose which source opens first.

**When to use it.** It works by itself: write an ordinary file input and uploads just work. You rarely call its actions; read its state if you want to show a spinner while a picker is open.

<EnvNew />

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `fileupload` package is on the global `window.dsx` and is built into every app:

```javascript
// built into every Despia V4 app
const dsx = window.dsx
if (dsx) {
  // Turns the native handling of file inputs on or off; when off, every file input opens the generic source sheet instead.
  const nativeOverwrite = await dsx.module.fileupload.nativeOverwrite({ native_overwrite: false })

  // Passes the accept and capture settings of the file input that was tapped, so the next pick opens the matching source.
  const captureInfo = await dsx.module.fileupload.captureInfo({ accept: "image/*", capture: "environment" })
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

## Actions

| Call | Arguments | Returns | Platforms | What it does |
| :-- | :-- | :-- | :-- | :-- |
| `dsx.module.fileupload.captureInfo()` | `accept`?: string<br/>`capture`?: string |  | iOS, Android | Passes the accept and capture settings of the file input that was tapped, so the next pick opens the matching source. |
| `dsx.module.fileupload.nativeOverwrite()` | `native_overwrite`?: boolean | `native_overwrite` | iOS, Android | Turns the native handling of file inputs on or off; when off, every file input opens the generic source sheet instead. |

## Action reference

<AccordionGroup>
<Accordion title="captureInfo">

Passes the accept and capture settings of the file input that was tapped, so the next pick opens the matching source.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `accept`? | string | The accept attribute of the tapped file input, such as image/*. |
| `capture`? | string | The capture attribute of the tapped file input, such as environment for the rear camera. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.fileupload.captureInfo({ accept: "image/*", capture: "environment" })
```

**Result:** `object`: shape not declared yet.

</Accordion>
<Accordion title="nativeOverwrite">

Turns the native handling of file inputs on or off; when off, every file input opens the generic source sheet instead.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `native_overwrite`? | boolean | True to narrow each input to the source its attributes ask for, false to always show the generic source sheet. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.fileupload.nativeOverwrite({ native_overwrite: false })
```

```json Result
{
  "native_overwrite": false
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `native_overwrite` | boolean | Whether native handling of file inputs is on right now. |

</Accordion>
</AccordionGroup>

## Configuration

Set these in the package settings of your app (see [Add a package](/packages/add-a-package)).

| Setting | What it is |
| :-- | :-- |
| Camera permission description (`camera_usage_description`) | Turns on the camera in file uploads and says why the app asks for it, for example: Use the camera to capture a photo you choose to upload. Empty (the default): file inputs offer the photo library and files only, and the app declares no camera permission. |

For apps built on Despia V3, see [Migrate from Despia V3](/packages/migrate-from-v3).
