Sets up your app's Firebase identity and registers each device with Firebase Cloud Messaging, so you can send pushes from the Firebase console or your server. Use it when your team already runs on Firebase. Needs a Firebase project; on Android it asks for the Firebase App ID, API key, project ID and sender ID, and on iOS your GoogleService-Info.plist.

**When to use it.** Use it when your team sends push notifications through Firebase Cloud Messaging. If you use another push provider such as OneSignal, you do not need it.

<EnvNew />

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `firebase` package is on the global `window.dsx`. `dsx.has('firebase')` is true when the package is in your app's build:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('firebase')) {
  // Returns this install's push subscription: its Firebase installation id, the FCM address your server sends to, and whether it is opted in.
  const subscriptionGet = await dsx.module.firebase.subscription.get()

  // Starts the shared Firebase app once and reports its identity. Other Firebase packages call it so initialisation happens in one place.
  const app = await dsx.module.firebase.app()

  // Opts this install in or out of Firebase push. Opting out deletes the FCM registration so Firebase stops addressing the device.
  const subscriptionSet = await dsx.module.firebase.subscription.set({ optedIn: false })
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

## Actions

| Call | Arguments | Returns | Platforms | What it does |
| :-- | :-- | :-- | :-- | :-- |
| `dsx.module.firebase.app()` | none | `appId`<br/>`configured`<br/>`projectId` | iOS, Android | Starts the shared Firebase app once and reports its identity. Other Firebase packages call it so initialisation happens in one place. |
| `dsx.module.firebase.subscription.get()` | none | `id`<br/>`optedIn`<br/>`token` | iOS, Android | Returns this install's push subscription: its Firebase installation id, the FCM address your server sends to, and whether it is opted in. |
| `dsx.module.firebase.subscription.set()` | `optedIn`: boolean | `id`<br/>`optedIn`<br/>`token` | iOS, Android | Opts this install in or out of Firebase push. Opting out deletes the FCM registration so Firebase stops addressing the device. |
| `dsx.module.firebase.topics.subscribe()` | `topic`: string | `topic` | iOS, Android | Subscribes this install to an FCM topic so you can send one message to everyone on it. |
| `dsx.module.firebase.topics.unsubscribe()` | `topic`: string | `topic` | iOS, Android | Removes this install from an FCM topic so it stops receiving that topic's messages. |

## Action reference

<AccordionGroup>
<Accordion title="app">

Starts the shared Firebase app once and reports its identity. Other Firebase packages call it so initialisation happens in one place.

**Arguments:** none.

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.firebase.app()
```

```json Result
{
  "appId": "1:1234567890:ios:abc123",
  "configured": true,
  "projectId": "despia-demo"
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `appId` | string | The Firebase app ID of this build. |
| `configured` | boolean | True when this build carries a usable Firebase identity. |
| `projectId` | string | The Firebase project ID of this build. |

**Errors**

| Code | Message |
| :-- | :-- |
| `not_configured` | This build carries no Firebase identity. Add GoogleService-Info.plist (Apple) or the android_app_id / android_api_key config keys (Android). |

</Accordion>
<Accordion title="subscription.get">

Returns this install's push subscription: its Firebase installation id, the FCM address your server sends to, and whether it is opted in.

**Arguments:** none.

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.firebase.subscription.get()
```

```json Result
{
  "id": "fid_abc",
  "optedIn": true,
  "token": "fcm_registration_abc"
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `id` | string | The Firebase installation id. Empty until Firebase has started. |
| `optedIn` | boolean | True when this app has push turned on with Firebase, which is separate from the system notification permission. |
| `token` | string | The FCM registration value your server uses to reach this device. Empty until Firebase has started. |

**Errors**

| Code | Message |
| :-- | :-- |
| `not_configured` | Firebase push is not enabled in this build: set config.push_enabled (and ship GoogleService-Info.plist or the android_* identity keys). |
| `unsupported_platform` | There is no FCM registration token on this runtime. |

</Accordion>
<Accordion title="subscription.set">

Opts this install in or out of Firebase push. Opting out deletes the FCM registration so Firebase stops addressing the device.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `optedIn` | boolean | True to turn push on, false to turn it off and delete the registration. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.firebase.subscription.set({ optedIn: false })
```

```json Result
{
  "id": "fid_abc",
  "optedIn": false,
  "token": ""
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `id` | string | The Firebase installation id after the change. |
| `optedIn` | boolean | Whether this install is now opted in. |
| `token` | string | The FCM registration value after the change, empty when opted out. |

**Errors**

| Code | Message |
| :-- | :-- |
| `missing_param` | Missing required parameter: optedIn (boolean). |
| `not_configured` | Firebase push is not enabled in this build: set config.push_enabled (and ship GoogleService-Info.plist or the android_* identity keys). |
| `unavailable` | Firebase could not delete the FCM token; the call can be retried. |
| `unsupported_platform` | There is no FCM registration token on this runtime. |

</Accordion>

| :-- | :-- | :-- |
| `topic` | string | The topic this install is now subscribed to. |

**Errors**

| Code | Message |
| :-- | :-- |

## Broadcasts

Listen with `window.dsx.module.firebase.on('<broadcast>', (data) => { ... })`. It returns a function that stops listening.

| Broadcast | When it fires |
| :-- | :-- |
| `subscription` | Fires when the FCM registration arrives, changes or is deleted, or when you change the opt-in. |

## Configuration

Set these in the package settings of your app (see [Add a package](/packages/add-a-package)).

| Setting | What it is |
| :-- | :-- |
| Android Firebase API key (`android_api_key`) | The Android app's Firebase API key, taken from google-services.json; it matches the API_KEY in the iOS plist. |
| Android Firebase App ID (`android_app_id`) | The Google App ID of the ANDROID app (Firebase console → Project settings → Your apps, e.g. 1:1234567890:android:abc123). Leave empty to keep Firebase push off on Android. |
| Android Firebase project ID (`android_project_id`) | The Firebase project ID (optional; needed for some Firebase services beyond plain FCM). |
| Android FCM sender ID (`android_sender_id`) | The Cloud Messaging sender ID, which is the numeric project number. It is optional because the app ID already includes it. |
| Append push id to URL (`enhance_url_with_push_id`) | Extend the WebView main URL with ?firebase_push_id=XYZ so the web app can read the FCM token. |
| FCM topic (`fcm_topic`) | Optional Firebase topic to subscribe every device to. |
| Firebase push enabled (`push_enabled`) | Activate Firebase Cloud Messaging push (download and replace GoogleService-Info.plist from the Firebase dashboard first). |

## What you need on your side

- A Firebase project with your Android app, and its app id, API key, project id and sender id in the package settings.
- Send pushes from your server through Firebase Cloud Messaging with a service account that stays on your server.

Despia never hosts your app, your backend or your users' content: the accounts and servers above are your own.

For apps built on Despia V3, see [Migrate from Despia V3](/packages/migrate-from-v3).
