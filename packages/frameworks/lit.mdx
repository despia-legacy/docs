## Where dsx code runs

`window.dsx` is only in the browser: the client web view of your app. Server rendering never sees it.

- Custom elements run in the browser. `connectedCallback` is the place to read `window.dsx`, and `disconnectedCallback` stops listening.
- With Lit server rendering, keep the check in `connectedCallback`, not in `render()`.

## Call a package and listen to a broadcast

```javascript done-button.js
import { LitElement, html, nothing } from 'lit'

class DoneButton extends LitElement {
  static properties = { env: { state: true }, busy: { state: true }, error: { state: true } }

  constructor() {
    super()
    this.env = 'web'
    this.busy = false
    this.error = null
  }

  connectedCallback() {
    super.connectedCallback()
    this.env = window.dsx ? 'v4' : 'web'
    this.off = window.dsx?.module.revenuecat.on('customerInfo', (data) => console.log(data))
  }

  disconnectedCallback() {
    super.disconnectedCallback()
    this.off?.()
  }

  async done() {
    this.busy = true
    this.error = null
    try {
      await window.dsx.module.haptic.success()
    } catch (e) {
      this.error = e.code
    } finally {
      this.busy = false
    }
  }

  render() {
    if (this.env !== 'v4') return nothing
    return html`<button ?disabled=${this.busy} @click=${this.done}>Done${this.error ? ` (${this.error})` : ''}</button>`
  }
}

customElements.define('done-button', DoneButton)
```

- **Environment check:** the component sets `env` in the browser only, so the server and the first browser render match.
- **Call:** `dsx.module.haptic.success()` with a busy state; a failed call rejects with an error that has a `code`.
- **Broadcast:** `dsx.module.revenuecat.on('customerInfo', ...)` returns a function that stops listening; it runs when the component goes away.

More in [How calls, results and broadcasts work](/packages/concepts).
