Every framework talks to Despia V4 the same way: through the global `window.dsx`, which the app installs before your first script runs. No package is needed for any framework: each guide gives you a few lines to copy.

## One rule for every stack

`window.dsx` exists only inside a Despia V4 app. Despia code runs in the browser (the app's web view), never on a server, so read `window.dsx` in an effect or event handler (`useEffect`, `onMounted`, `onMount`, a click handler), never during render. Then server-rendered frameworks never reach it on the server, and server and browser output match.

## Pick your guide

| Your stack | Guide | You copy |
| :-- | :-- | :-- |
| React, Next.js, Remix | [React and Next.js](/packages/frameworks/react) | `useDsxCall`, `useDsxBroadcast` hooks |
| Vue 3, Nuxt | [Vue and Nuxt](/packages/frameworks/vue) | `useDsxCall`, `useDsxBroadcast` composables |
| Svelte, SvelteKit | [Svelte and SvelteKit](/packages/frameworks/svelte) | `dsxCall`, `onDsxBroadcast` |
| Angular | [Angular](/packages/frameworks/angular) | a `DespiaService` with zone handling |
| SolidJS, SolidStart | [SolidJS](/packages/frameworks/solid) | `createDsxCall`, `onDsxBroadcast` |
| Plain HTML, vanilla JS, Astro, jQuery, anything else | [Plain HTML, vanilla JS and Astro](/packages/frameworks/html) | nothing: call `window.dsx` from a script |

Lovable and Base44 generate React apps, so use the React guide.

## What every guide covers

- **Environment check**: the check at the top of the page (Despia V4 or a normal browser).
- **Calling a package** with loading and error state. A failed call rejects with an object that has a `code`.
- **Broadcasts** with cleanup when the component goes away.
- **Server rendering**: where it is safe to read `window.dsx`.
- **TypeScript**: a declaration of `window.dsx` that matches the runtime.

The calls themselves are the same everywhere and are listed on each [package page](/packages/overview).
