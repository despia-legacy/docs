Every framework talks to Despia V4 the same way: through the global `window.dsx`, which the app installs before your first script runs. No package is needed for any framework: each guide gives you a few lines to copy.

## One rule for every stack

Today, `window.dsx` is present only inside the Despia V4 app. In a web view app it is only in the browser (the app's web view), so read `window.dsx` in an effect or event handler (`useEffect`, `onMounted`, `onMount`, a click handler), never during render. Then server-rendered frameworks never reach it on the server, and server and browser output match.

## What every guide covers

- **Environment check**: the check at the top of the page (Despia V4 or a normal browser).
- **Calling a package** with loading and error state. A failed call rejects with an object that has a `code`.
- **Broadcasts** with cleanup when the component goes away.
- **Server rendering**: where it is safe to read `window.dsx`.
- **TypeScript**: a declaration of `window.dsx` that matches the runtime.

The calls themselves are the same everywhere and are listed on each [package page](/packages/overview).
