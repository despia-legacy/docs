## Where dsx code runs

Only in the browser: the client web view of your app, never during server rendering.

- Component bodies render on the server, and `routeLoader$`, `routeAction$` and `server$` always run there: never read `window.dsx` in them.
- `useVisibleTask$` and event handlers run only in the browser.

## Call a package and listen to a broadcast

```tsx src/components/done-button.tsx
import { $, component$, useSignal, useVisibleTask$ } from '@builder.io/qwik'

export const DoneButton = component$(() => {
  const env = useSignal<'v4' | 'web'>('web')
  const busy = useSignal(false)
  const error = useSignal<string | null>(null)

  // useVisibleTask$ runs only in the browser
  useVisibleTask$(({ cleanup }) => {
    env.value = window.dsx ? 'v4' : 'web'
    const off = window.dsx?.module.revenuecat.on('customerInfo', (data: unknown) => console.log(data))
    cleanup(() => off?.())
  })

  const done = $(async () => {
    busy.value = true
    error.value = null
    try {
      await window.dsx!.module.haptic.success()
    } catch (e: any) {
      error.value = e.code
    } finally {
      busy.value = false
    }
  })

  if (env.value !== 'v4') return null
  return <button disabled={busy.value} onClick$={done}>Done{error.value && ` (${error.value})`}</button>
})
```

- **Environment check:** the component sets `env` in the browser only, so the server and the first browser render match.
- **Call:** `dsx.module.haptic.success()` with a busy state; a failed call rejects with an error that has a `code`.
- **Broadcast:** `dsx.module.revenuecat.on('customerInfo', ...)` returns a function that stops listening; it runs when the component goes away.

More in [How calls, results and broadcasts work](/packages/concepts).
