## Where dsx code runs

Only in the browser: the client web view of your app, never during server rendering.

- `loader` and `action` run on the server: never read `window.dsx` there.
- `clientLoader` and `clientAction` run in the browser and may read it; in components use `useEffect` or an event handler.

## Call a package and listen to a broadcast

```jsx app/components/DoneButton.jsx
import { useEffect, useState } from 'react'

export function DoneButton() {
  const [env, setEnv] = useState('web')
  const [busy, setBusy] = useState(false)
  const [error, setError] = useState(null)

  useEffect(() => {
    setEnv(window.dsx ? 'v4' : 'web')
    return window.dsx?.module.revenuecat.on('customerInfo', (data) => console.log(data))
  }, [])

  async function done() {
    setBusy(true)
    setError(null)
    try {
      await window.dsx.module.haptic.success()
    } catch (e) {
      setError(e.code)
    } finally {
      setBusy(false)
    }
  }

  if (env !== 'v4') return null // normal browser: web code
  return <button disabled={busy} onClick={done}>Done{error && ` (${error})`}</button>
}
```

- **Environment check:** the component sets `env` in the browser only, so the server and the first browser render match.
- **Call:** `dsx.module.haptic.success()` with a busy state; a failed call rejects with an error that has a `code`.
- **Broadcast:** `dsx.module.revenuecat.on('customerInfo', ...)` returns a function that stops listening; it runs when the component goes away.

More in [How calls, results and broadcasts work](/packages/concepts).
