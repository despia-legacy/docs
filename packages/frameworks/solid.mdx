## Where dsx code runs

`window.dsx` is only in the browser: the client web view of your app. Server rendering never sees it.

- `onMount` runs only in the browser, so the component is safe with SolidStart.
- Never read `window.dsx` in a component body or in a `"use server"` function.

## Call a package and listen to a broadcast

```jsx DoneButton.jsx
import { createSignal, onCleanup, onMount, Show } from 'solid-js'

export function DoneButton() {
  const [env, setEnv] = createSignal('web')
  const [busy, setBusy] = createSignal(false)
  const [error, setError] = createSignal(null)

  onMount(() => {
    setEnv(window.dsx ? 'v4' : 'web')
    const off = window.dsx?.module.revenuecat.on('customerInfo', (data) => console.log(data))
    onCleanup(() => off?.())
  })

  async function done() {
    setBusy(true)
    setError(null)
    try {
      await window.dsx.module.haptic.success()
    } catch (e) {
      setError(e.code)
    } finally {
      setBusy(false)
    }
  }

  return (
    <Show when={env() === 'v4'}>
      <button disabled={busy()} onClick={done}>Done{error() && ` (${error()})`}</button>
    </Show>
  )
}
```

- **Environment check:** the component sets `env` in the browser only, so the server and the first browser render match.
- **Call:** `dsx.module.haptic.success()` with a busy state; a failed call rejects with an error that has a `code`.
- **Broadcast:** `dsx.module.revenuecat.on('customerInfo', ...)` returns a function that stops listening; it runs when the component goes away.

More in [How calls, results and broadcasts work](/packages/concepts).
