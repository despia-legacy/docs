## Where dsx code runs

Only in the browser: the client web view of your app, never during server rendering.

- A Vue app built with Vite renders in the browser; `onMounted` and event handlers run there.
- Read `window.dsx` in `onMounted` or a handler, not at the top of `setup`.

## Call a package and listen to a broadcast

```vue DoneButton.vue
<script setup>
import { onMounted, onUnmounted, ref } from 'vue'

const env = ref('web')
const busy = ref(false)
const error = ref(null)
let off

onMounted(() => {
  env.value = window.dsx ? 'v4' : 'web'
  off = window.dsx?.module.revenuecat.on('customerInfo', (data) => console.log(data))
})
onUnmounted(() => off?.())

async function done() {
  busy.value = true
  error.value = null
  try {
    await window.dsx.module.haptic.success()
  } catch (e) {
    error.value = e.code
  } finally {
    busy.value = false
  }
}
</script>

<template>
  <button v-if="env === 'v4'" :disabled="busy" @click="done">Done<span v-if="error"> ({{ error }})</span></button>
</template>
```

- **Environment check:** the component sets `env` in the browser only, so the server and the first browser render match.
- **Call:** `dsx.module.haptic.success()` with a busy state; a failed call rejects with an error that has a `code`.
- **Broadcast:** `dsx.module.revenuecat.on('customerInfo', ...)` returns a function that stops listening; it runs when the component goes away.

More in [How calls, results and broadcasts work](/packages/concepts).
