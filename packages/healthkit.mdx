<Note>Verified on iOS. The Android implementation (Health Connect) is Alpha: an early implementation that may change and is provided without a service level guarantee. Report bugs to bugs@despia.com.</Note>

<Info>Modern API. Requires Despia V4 or greater. Despia V4 is currently a pre-release (0.0.2), stable for web view apps. Check for it first, see [Detect Despia V4](/packages/overview#detect-despia-v4).</Info>

Reads steps, heart rate, sleep and workouts, saves measurements, and can send new samples to your server in the background. The same type names work on iOS and Android, and the first read of a type asks the person for permission. Needs a health usage description for iOS; iPads and some Android phones have no health store.

**When to use it.** Add it when your app shows or records health and fitness data on the device, or forwards it to your backend. If you want data from wearable brands through a cloud service, look at the Terra package instead.

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `healthkit` package is on the global `window.dsx`. `dsx.has('healthkit')` is true when the package is in your app's build:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('healthkit')) {
  // Reads health data for the types you list, as daily totals or as individual samples.
  const readResult = await dsx.module.healthkit.read({ days: 2, types: ["HKQuantityTypeIdentifierStepCount"] })

  // Saves one health value, such as a weight, to Apple Health or Health Connect.
  const writeResult = await dsx.module.healthkit.write({ type: "HKQuantityTypeIdentifierBodyMass", value: 75.5 })

  // Reports whether health data exists on this device and which types are allowed.
  const statusResult = await dsx.module.healthkit.status({ types: ["HKQuantityTypeIdentifierStepCount"] })
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

## Action reference

<AccordionGroup>
<Accordion title="observe">

Watches health types in the background and sends new samples to your server over HTTPS.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `frequency`? | string | How often to deliver: immediate, hourly, daily or weekly; defaults to immediate. |
| `server`? | string | The absolute HTTPS address that receives the data; it is remembered across launches. |
| `types` | array | Health type identifiers such as HKQuantityTypeIdentifierStepCount; the same names are used on iOS and Android. |
| `userId`? | string | Your id for the person, sent with the data; a random app-installation id is used when you leave it out. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.healthkit.observe({ frequency: "immediate", server: "https://example.com/hook", types: ["HKQuantityTypeIdentifierStepCount"], userId: "account-fixture-123" })
```

**Result:** nothing.

</Accordion>
<Accordion title="permission.manage">

Lets the person change a limited selection where the system has one; otherwise returns the current state unchanged.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `types`? | array | Health type identifiers such as HKQuantityTypeIdentifierStepCount; the same names are used on iOS and Android. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.healthkit.permission.manage()
```

```json Result
{
  "canAsk": false,
  "changed": false,
  "status": "granted"
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `canAsk` | boolean | True while the system dialog can still be shown; false once the person has refused it. |
| `changed` | boolean | True when the selection was changed; false where the platform has no limited selection. |
| `level`? | string | Access level where the platform offers more than all-or-nothing; empty otherwise. |
| `status` | string | Current permission: undetermined, granted, denied, restricted or unavailable. |

</Accordion>

<Accordion title="write">

Saves one health value, such as a weight, to Apple Health or Health Connect.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `type` | string | The health type identifier to save, for example HKQuantityTypeIdentifierBodyMass. |
| `unit`? | string | The unit of the value, for example kg; leave out to use the type's default unit. |
| `value` | number | The number to save, in the unit of the type or the unit you give. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.healthkit.write({ type: "HKQuantityTypeIdentifierBodyMass", value: 75.5 })
```

```json Result
{
  "type": "HKQuantityTypeIdentifierBodyMass",
  "value": 75.5,
  "written": true
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `type` | string | The health type that was written. |
| `value` | number | The number that was saved. |
| `written` | boolean | True when the value was saved. |

**Errors**

| Code | Message |
| :-- | :-- |
| `healthkit_unavailable` | Health data is not available on this device. |
| `invalid_argument` | Pass a type identifier and a numeric value. |
| `invalid_type` | That type cannot be written on this device. |
| `permission_denied` | The user has not allowed this app to write that type. |
| `write_failed` | The health store refused the value. |

</Accordion>

## Broadcasts

Listen with `window.dsx.module.healthkit.on('<broadcast>', (data) => { ... })`. It returns a function that stops listening.

| Broadcast | When it fires |
| :-- | :-- |
| `observing` | The list of health types being watched for background delivery changed, after observe or unobserve. |
| `unavailable` | Health data is not available on this device, for example on an iPad without the Health app or an Android phone without Health Connect. The call that found out also fails with the same code. |

## Configuration

Set these in the package settings of your app (see [Add a package](/packages/add-a-package)).

| Setting | What it is |
| :-- | :-- |
| Health read prompt (`usage_share_description`) | The message shown when iOS asks permission to read Health data. |
| Health write prompt (`usage_update_description`) | The message shown when iOS asks permission to save data to Health. |

For apps built on Despia V3, see [Migrate from Despia V3](/packages/migrate-from-v3).
