<EnvMigration />

## What keeps working

- **Your `despia('scheme://...')` calls.** The Legacy polyfill answers the Despia V3 URL schemes and `despia('scheme://...')` calls (see the Legacy tab), so a Despia V3 page runs unchanged. The [Legacy to Modern map](/packages/legacy-map) lists every scheme it answers.
- **Your Despia V3 callbacks and globals.** The polyfill turns Despia V4 broadcasts back into the Despia V3 events and callbacks (`window.focusin()`, `onNotificationEvent`, `updateRewardedStatus`, ...). See [Broadcasts](/packages/broadcasts).
- **Push taps.** A tapped push still routes the page to its `path` and calls `onNotificationEvent`. See [Push notifications](/packages/push-notifications).

## What changed

| Change | What to do |
| :-- | :-- |
| `inapppurchase://` and `inappsubscription://` are removed. Nothing answers them in Despia V4. | Buy through RevenueCat: `dsx.module.revenuecat.purchase({ product })` (see [RevenueCat](/packages/revenuecat)), or on a Despia V3 page `despia('revenuecat://purchase?external_id=<user>&product=<id>')`. |
| `getpurchasehistory://`, `restoreinapppurchases://`, `revenuecat://` and `cancelinapppurchase://` are kept. | Nothing. |
| `@despia/powersync` is **discontinued** and not available in Despia V4. Despia is building its own open-source local database. | Stay on your current Despia V3 build until the replacement is available, or move the data to your own backend API or to IndexedDB. |
| The local server is HTTPS only. | Nothing for most apps. Do not hard-code `http://` addresses to the local server. |
| Accessibility uses ARIA. | Write standard `aria-*` and `role` attributes. The older `a11y*` attributes are still read until 1.0.0. |

## What the conversion warns about

When a Despia V3 app is converted to Despia V4, the conversion reads your pages and your Despia V3 settings and reports what will not work, rather than converting it silently:

- **`iap_purchase_verb_removed`**: a page still calls `inapppurchase://` or `inappsubscription://`. The warning names each page and the RevenueCat replacement.
- **`powersync_not_supported`**: a page uses `@despia/powersync` (or `window.nativeBridgeResponse` / `window.nativeBridgeEvent`), or the Despia V3 settings carry a `@despia/powersync` app id. `@despia/powersync` is discontinued; the warning names the pages and the options above.

## Custom paywalls: `revenuecat://offerings`

Despia V3 custom web paywalls set `window.onRevenueCatOfferings`, called `despia('revenuecat://offerings?offering=<id>')`, and read `offeringsData` (or `offeringsError`) in the callback. Despia V4 answers this on iOS and Android with the same entries: `packageId`, `packageType`, `productId`, `title`, `priceString`, `price`, `currency`, `period { unit, value, iso8601 }`, `pricePerUnitString` and `introOffer`.

The modern call is `dsx.module.revenuecat.offerings()`:

```javascript
if (window.dsx) {
  const offerings = await window.dsx.module.revenuecat.offerings()
} else if (navigator.userAgent.includes("despia")) {
  window.onRevenueCatOfferings = () => render(window.offeringsData, window.offeringsError)
  despia("revenuecat://offerings")
}
```

## Move a call to the Modern API

There is no deadline: the Legacy API keeps working. When you touch a feature, look its scheme up in the [Legacy to Modern map](/packages/legacy-map), call the modern API on Despia V4, and keep the Despia V3 call in the `else` branch as the runtime block shows.
