<Info>Modern API. Requires Despia V4 or greater. Despia V4 is currently a pre-release (0.1.0), stable for web view apps. Check for it first, see [Detect Despia V4](/packages/overview#detect-despia-v4).</Info>

Streams motion sensor data at the rate you choose, and reads the barometer, step count and activity type such as walking or driving. Use it for fitness, games and gesture features. Asks for motion permission when needed, with text you set. Phones only.

**When to use it.** Use it for fitness, games, gestures and movement-aware features that need motion data at a rate you choose. For a one-off compass or orientation reading on a page, the browser sensors may be enough.

<EnvNew />

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `motion` package is on the global `window.dsx`. `dsx.has('motion')` is true when the package is in your app's build:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('motion')) {
  // Starts one motion stream with the sensors and sampling rate you choose, and sends each sample as a single object.
  const startResultSub = dsx.module.motion.start({ hz: 60, sensors: ["accelerometer", "gyroscope"] }, (event) => {
    console.log(event.event, event.data)
  })
  // later: startResultSub.stop()

  // Stops the motion stream and releases the sensors.
  const stopResult = await dsx.module.motion.stop()

  // Reports which motion sensors this device has and the highest sampling rate it allows.
  const capabilities = await dsx.module.motion.capabilities()
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

## Action reference

<AccordionGroup>
<Accordion title="activity">

Starts or stops classification of what the person is doing, such as walking, running, cycling or driving.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `on`? | boolean | True starts the classification and false stops it. |
| `prompt`? | boolean | True lets the system permission dialog appear on this call when it can; false never shows it and fails if access is missing. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.motion.activity({ on: true })
```

**Result:** a stream. Pass a handler as the second argument; it receives each update.

**Errors**

| Code | Message |
| :-- | :-- |
| `permission_denied` | Motion & fitness access is not granted. The data carries the contract state: &#123; permission, status, canAsk &#125;. |
| `start_failed` | Activity recognition could not be started. |
| `unsupported_device` | Activity recognition is not available on this device. |
| `unsupported_platform` | This runtime has no sensor of that kind. |

</Accordion>

<Accordion title="capabilities">

Reports which motion sensors this device has and the highest sampling rate it allows.

**Arguments:** none.


```json Result
{
  "accelerometer": true,
  "activity": true,
  "barometer": true,
  "deviceMotion": true,
  "gyroscope": true,
  "magnetometer": true,
  "maxHz": 100,
  "pedometer": true

```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `accelerometer` | boolean | True when the device has an accelerometer. |
| `activity` | boolean | True when the device can tell walking from driving and similar activities. |
| `barometer` | boolean | True when the device has an air pressure sensor. |
| `deviceMotion` | boolean | True when the device can report fused motion such as attitude and gravity. |
| `gyroscope` | boolean | True when the device has a gyroscope. |
| `magnetometer` | boolean | True when the device has a magnetometer or compass. |
| `maxHz` | number | The highest sampling rate in hertz that start may use. |
| `pedometer` | boolean | True when the device can count steps. |

</Accordion>
<Accordion title="pedometer">

Reads the steps, distance and floors the person has covered since a moment you choose.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `from`? | number | The start of the period to count, as a time in milliseconds since 1970; leave it out for a default period. |
| `prompt`? | boolean | True lets the system permission dialog appear on this call when it can; false never shows it and fails if access is missing. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.motion.pedometer({ from: 1700000000000 })
```

```json Result
{
  "distance": 2410.5,
  "end": 1700003600000,
  "floorsAscended": 3,
  "floorsDescended": 1,
  "start": 1700000000000,
  "steps": 3120
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `distance` | number | The distance walked or run in the period, in meters. |
| `end` | number | The end of the counted period, in milliseconds since 1970. |
| `floorsAscended` | number | The number of floors climbed up in the period. |
| `floorsDescended` | number | The number of floors walked down in the period. |
| `start` | number | The start of the counted period, in milliseconds since 1970. |
| `steps` | number | The number of steps taken in the period. |

**Errors**

| Code | Message |
| :-- | :-- |
| `no_reading` | The step counter delivered no reading. |
| `permission_denied` | Motion & fitness access is not granted. The data carries the contract state: &#123; permission, status, canAsk &#125;. |
| `unsupported_device` | Step counting is not available on this device. |
| `unsupported_platform` | This runtime has no sensor of that kind. |

</Accordion>

<Accordion title="start">

Starts one motion stream with the sensors and sampling rate you choose, and sends each sample as a single object.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `buffer`? | number | While the app is in the background, seconds between the samples that are kept for later. |
| `cap`? | number | How many samples to keep while in the background; the oldest are dropped and counted. |
| `hz`? | number | How many samples per second to take; it is capped by the maximum sampling rate setting. |
| `sensors`? | string[] | The sensor blocks to include in each sample, such as accelerometer, gyroscope, magnetometer, attitude, gravity or userAcceleration. |
| `server`? | string | A web address that the app posts the background samples to by itself, even if the app is never reopened. |
| `threshold`? | number | A movement size in g below which samples are skipped, so a still phone sends nothing. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.motion.start({ hz: 60, sensors: ["accelerometer", "gyroscope"] })
```

**Result:** a stream. Pass a handler as the second argument; it receives each update.

**Errors**

| Code | Message |
| :-- | :-- |
| `permission_denied` | Motion and orientation access was not granted. |
| `unsupported_device` | This device has none of the requested motion sensors. |
| `unsupported_sensor` | One of the requested sensors is not a known sensor name. |

</Accordion>

## Broadcasts

Listen with `window.dsx.module.motion.on('<broadcast>', (data) => { ... })`. It returns a function that stops listening.

| Broadcast | When it fires |
| :-- | :-- |
| `activity` | Delivers the activity the device thinks the person is doing, each time it changes. |
| `batch` | Delivers the samples kept while the app was in the background, as one event when the app comes back or the stream stops. |
| `calibration` | Tells you the compass heading has become unreliable and the device needs to be moved in a figure of eight. |
| `change` | Delivers one sample of the sensors you asked for while the app is open. |
| `pressure` | Delivers one air pressure reading while the barometer stream is on. |

## Configuration

Set these in the package settings of your app (see [Add a package](/packages/add-a-package)).

| Setting | What it is |
| :-- | :-- |
| Background enabled (`background_enabled`) | Keep the motion stream alive while the app is in the background. |
| Background notification text (`background_notification_text`) | Body of the ongoing Android notification shown while motion is tracked in the background. |
| Background notification title (`background_notification_title`) | Title of the ongoing Android notification shown while motion is tracked in the background. |
| Maximum sampling rate (`max_hz`) | Upper bound, in hertz, on the sampling rate a page may ask for. |
| Motion & fitness prompt (`usage_motion`) | The message shown when iOS asks for motion & fitness access. |

For apps built on Despia V3, see [Migrate from Despia V3](/packages/migrate-from-v3).
