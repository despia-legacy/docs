<Info>Modern API. Requires Despia V4 or greater. Despia V4 is currently a pre-release (0.0.2), stable for web view apps. Check for it first, see [Detect Despia V4](/packages/overview#detect-despia-v4).</Info>

Finds nearby devices that run the same app, connects them and lets them exchange small messages, using Nearby Connections on Android and MultipeerConnectivity on iOS with the same calls. iPhones only connect to iPhones and Android phones to Android phones. You write the screens for picking a peer and the messages you send.

**When to use it.** Reach for it for local multiplayer, file-less data sharing or classroom-style features between devices in the same room. Do not use it when an iPhone must talk to an Android phone, because the two systems cannot find each other; use a server for that.

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `nearby` package is on the global `window.dsx`. `dsx.has('nearby')` is true when the package is in your app's build:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('nearby')) {
  // Starts the single nearby session: advertises this device, looks for others, or both, and streams what it finds as events.
  const startResultSub = dsx.module.nearby.start({ mode: "both", name: "Alice", strategy: "star" }, (event) => {
    console.log(event.event, event.data)
  })
  // later: startResultSub.stop()

  // Asks a discovered device to connect. Connections are accepted automatically, so any device running the same app and service id can join.
  const connect = await dsx.module.nearby.connect({ peer: "4a2f" })

  // Closes the connection to one device, or to every connected device when no peer is given.
  const disconnect = await dsx.module.nearby.disconnect({ peer: "4a2f" })
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

## Actions

| Call | Arguments | Returns | Platforms | What it does |
| :-- | :-- | :-- | :-- | :-- |
| `dsx.module.nearby.capabilities()` | none | `maxPayloadBytes`<br/>`strategies` | iOS, Android | Reports what this device's nearby connection can do, such as the largest message and the connection strategies on offer. |
| `dsx.module.nearby.connect()` | `peer`: string | `connected`<br/>`peer` | iOS, Android | Asks a discovered device to connect. Connections are accepted automatically, so any device running the same app and service id can join. |
| `dsx.module.nearby.disconnect()` | `peer`?: string | `disconnected` | iOS, Android | Closes the connection to one device, or to every connected device when no peer is given. |
| `dsx.module.nearby.permission.manage()` | none | `canAsk`<br/>`changed`<br/>`level`<br/>`status` | iOS, Android | Lets the person change a limited selection of what the app can access, where the system offers that, and otherwise just reports the current state. |
| `dsx.module.nearby.permission.openSettings()` | none | `opened` | iOS, Android | Opens this app's page in the system Settings so the person can change a permission they refused earlier. |
| `dsx.module.nearby.permission.request()` | none | `canAsk`<br/>`level`<br/>`status` | iOS, Android | Asks the person for nearby device access through the system prompt and reports the answer. |
| `dsx.module.nearby.permission.status()` | none | `canAsk`<br/>`level`<br/>`status` | iOS, Android | Reports whether the app currently has nearby device access without asking the person. |
| `dsx.module.nearby.send()` | `data`: string<br/>`peer`?: string | `bytes`<br/>`sent` | iOS, Android | Sends a message to one connected device, or to all of them when no peer is given. |
| `dsx.module.nearby.start()` | `mode`?: string<br/>`name`?: string<br/>`prompt`?: boolean<br/>`strategy`?: string | stream (sends `peerFound`, `peerLost`, `connecting`, `connected`, `disconnected`, `payload`) | iOS, Android | Starts the single nearby session: advertises this device, looks for others, or both, and streams what it finds as events. |
| `dsx.module.nearby.stop()` | none | `active` | iOS, Android | Ends the nearby session and disconnects everyone. |

## Action reference

<AccordionGroup>
<Accordion title="capabilities">

Reports what this device's nearby connection can do, such as the largest message and the connection strategies on offer.

**Arguments:** none.

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.nearby.capabilities()
```

```json Result
{
  "maxPayloadBytes": 32768,
  "strategies": [
    "star",
    "cluster",
    "p2p"
  ]
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `maxPayloadBytes` | number | The largest message you can send, in bytes. |
| `strategies` | string[] | The connection strategies this device supports. |

</Accordion>
<Accordion title="connect">

Asks a discovered device to connect. Connections are accepted automatically, so any device running the same app and service id can join.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `peer` | string | The id of a device from a peerFound event. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.nearby.connect({ peer: "4a2f" })
```

```json Result
{
  "connected": true,
  "peer": {
    "id": "4a2f",
    "name": "Bob"
  }
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `connected` | boolean | True once the connection is made. |
| `peer` | object | The device you connected to, with its id and name. |

**Errors**

| Code | Message |
| :-- | :-- |
| `connection_failed` | The connection could not be established. |
| `not_started` | No nearby session is running. |
| `peer_not_found` | No discovered peer has that id. |

</Accordion>
<Accordion title="disconnect">

Closes the connection to one device, or to every connected device when no peer is given.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `peer`? | string | The id of the device to disconnect. Leave it out to disconnect all. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.nearby.disconnect({ peer: "4a2f" })
```

```json Result
{
  "disconnected": 1
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `disconnected` | number | How many connections were closed. |

</Accordion>
<Accordion title="permission.manage">

Lets the person change a limited selection of what the app can access, where the system offers that, and otherwise just reports the current state.

**Arguments:** none.

**Example** (from the package's own test)


| Code | Message |
| :-- | :-- |

<Accordion title="start">

Starts the single nearby session: advertises this device, looks for others, or both, and streams what it finds as events.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `mode`? | string | Whether to advertise, discover or do both. Defaults to both. |
| `name`? | string | The name other devices see for this one. Defaults to the device name. |
| `prompt`? | boolean | Set to false to fail with permission_denied instead of showing the system permission dialog. |
| `strategy`? | string | On Android, how devices connect: star, cluster or p2p. iOS ignores it. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.nearby.start({ mode: "both", name: "Alice", strategy: "star" })
```

**Result:** a stream. Pass a handler as the second argument; it receives each update.

**Errors**

| Code | Message |
| :-- | :-- |
| `busy` | A nearby session is already running. |
| `invalid_argument` | mode must be advertise\|discover\|both; strategy star\|cluster\|p2p. |
| `permission_denied` | Nearby access is not granted. The data carries the contract state: &#123; permission, status, canAsk &#125;. |
| `switched_off` | Bluetooth is turned off. |
| `unavailable` | Nearby could not start right now. |
| `unsupported_device` | This device cannot run a nearby session: no Google Play services, or no Bluetooth or Wi-Fi radio to discover and advertise over. |

</Accordion>

## Broadcasts

Listen with `window.dsx.module.nearby.on('<broadcast>', (data) => { ... })`. It returns a function that stops listening.

| Broadcast | When it fires |
| :-- | :-- |
| `connected` | The connection to a device is established and you can send messages. |
| `connecting` | A connection to a device is being set up. |
| `disconnected` | A device disconnected, or a connection attempt ended without connecting on iOS. |
| `payload` | A message arrived from a connected device. |
| `peerFound` | A nearby device running the same app and service id was found. |
| `peerLost` | A device that had been found has stopped advertising or gone out of range. |

## Configuration

Set these in the package settings of your app (see [Add a package](/packages/add-a-package)).

| Setting | What it is |
| :-- | :-- |
| Service id (`service_id`) | The identifier peers use to find each other. Both sides of a connection must use the same value. |
| Local network prompt (`usage_local_network`) | The message shown when iOS asks for local-network access. |

For apps built on Despia V3, see [Migrate from Despia V3](/packages/migrate-from-v3).
