<Info>Modern API. Requires Despia V4 or greater. Despia V4 is currently a pre-release (0.0.2), stable for web view apps. Check for it first, see [Detect Despia V4](/packages/overview#detect-despia-v4).</Info>

Handles the notification permission, the device token, Android channels, action buttons, badges, images, scheduled notifications and what happens when a user taps one. Use it when you want notifications built in rather than through OneSignal, Pushwoosh or Firebase. You send pushes from your own server with your own Apple push key.

**When to use it.** Reach for it when your app needs to remind, alert or message people outside the app, from your own server or from the device itself. If you already use a push vendor, keep it and use this package only for the local side.

<EnvNew />

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `notify` package is on the global `window.dsx`. `dsx.has('notify')` is true when the package is in your app's build:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('notify')) {
  // Asks the user to allow notifications and tells you where that leaves you. With provisional set on iOS, notifications are allowed quietly without showing a prompt.
  const permissionRequest = await dsx.module.notify.permission.request({ provisional: true })

  // Reads the current notification permission without ever showing a prompt. Use it on a settings screen to show whether notifications are on.
  const permissionStatus = await dsx.module.notify.permission.status()

  // Reads the number currently shown on the app icon. Where the system cannot report it, the package returns the last number it set.
  const badgeGet = await dsx.module.notify.badge.get()
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

<Accordion title="channels.set">

Creates or updates an Android notification channel, which controls the importance, sound and vibration of a kind of notification. Android lets you lower a channel but ignores raising it, so the result tells you what the channel will really be.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |

| `group`? | string | The id of a channel group to list this channel under. |

| `importance`? | string | How loud the channel is: none, min, low, default, high or max. |
| `lights`? | boolean | Whether notifications on this channel flash the device light. |
| `name`? | string | The channel name the user sees in system settings. |
| `sound`? | string | The sound the channel plays, or an empty value for silence. |
| `vibration`? | boolean | Whether notifications on this channel vibrate. |

<Accordion title="present">

Shows a notification on this device right now, without a server. It can carry a title, body, image, action buttons and a channel.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `attachments`? | string[] | Image or media URLs to attach; if one cannot be fetched the notification shows without it. |
| `badge`? | number | A number to put on the app icon with this notification. |
| `body`? | string | The main text under the title. |
| `category`? | string | The id of a button set made with categories.set. |
| `channel`? | string | The Android channel to post to; it must already exist. |
| `chip`? | string | Android only: short text for the status bar chip of a promoted notification. |
| `data`? | object | Your own values, handed back to you on the opened event when the user taps it. |
| `id`? | string | Your own id for the notification, used later to dismiss it; one is made if you leave it out. |
| `interruption`? | string | How urgent it is on iOS: passive, active, timeSensitive or critical. |
| `ongoing`? | boolean | Android only: keep the notification in the shade so the user cannot swipe it away. |
| `progress`? | number | Android only: a progress value to show in the notification. |
| `promote`? | boolean | Android only: ask the system to show it as a live, promoted notification where supported. |
| `prompt`? | boolean | Ask for permission first if the user has not been asked yet. |
| `sound`? | string | The sound to play, or the default sound if you leave it out. |
| `subtitle`? | string | A line between the title and the body, shown on iOS. |
| `thread`? | string | A group name, so related notifications stack together. |
| `title` | string | The headline of the notification, shown in bold at the top. |
| `views`? | object | Android only: custom layouts for the collapsed and expanded notification, passed in by another native package. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.notify.present({ body: "Chapter 12", data: {"path": "/episode/42"}, id: "ep-42", title: "New episode" })
```

```json Result
{
  "id": "ep-42",
  "presented": true
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `id` | string | The id the notification was shown with, which you can pass to dismiss later. |
| `presented` | boolean | True if the system accepted the notification for display. |

**Errors**

| Code | Message |
| :-- | :-- |
| `attachment_failed` | The attachment could not be fetched; the notification was shown without it. |
| `channel_required` | That Android channel was never created, and the OS drops a notification posted to an unknown channel silently. Call channels.set first. |
| `invalid_argument` | Notification progress must be a number from 0 to 1. |
| `permission_denied` | Notifications are off for this app, so nothing would be shown. |
| `presentation_failed` | Android could not present the notification. |
| `unsupported_platform` | This surface cannot show notifications. |

| `cron`? | string | A five field cron pattern with minute precision. |
| `data`? | object | Your own values, handed back on the opened event. |
| `id`? | string | Your own id, used later to cancel it; one is made if you leave it out. |
| `in`? | number | How many seconds from now to fire. |
| `interruption`? | string | How urgent it is on iOS: passive, active, timeSensitive or critical. |
| `prompt`? | boolean | Ask for permission first if the user has not been asked yet. |
| `repeats`? | string | Repeat every hourly, daily, weekly, monthly or yearly; it cannot be combined with cron. |
| `sound`? | string | The sound to play, or the default sound. |
| `subtitle`? | string | A line between the title and the body, shown on iOS. |
| `thread`? | string | A group name, so related notifications stack together. |
| `timezone`? | string | The time zone name used to read a wall-clock time. |
| `title` | string | The headline of the notification, shown in bold at the top. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.notify.schedule({ at: "2026-06-01T12:00:00Z", id: "ep-42", title: "New episode" })
```

  "nextFire": 1780315200000,
  "repeating": false
}

| Field | Type | Description |
| :-- | :-- | :-- |
| `id` | string | The id of the scheduled notification. |
| `nextFire` | number | When it will next fire, as epoch milliseconds. |
| `repeating` | boolean | True if it will fire more than once. |

**Errors**

| Code | Message |
| :-- | :-- |

| `invalid_trigger` | A schedule needs exactly one of at, in or cron; repeats must be hourly, daily, weekly, monthly or yearly, and cannot ride a cron. |
| `permission_denied` | Notifications are off for this app, so a scheduled notification would never be shown. |
| `unsupported_platform` | This surface cannot schedule notifications. |

## Broadcasts

Listen with `window.dsx.module.notify.on('<broadcast>', (data) => { ... })`. It returns a function that stops listening.

| Broadcast | When it fires |
| :-- | :-- |
| `dismissed` | The user dismissed a notification without opening it. |
| `opened` | The user tapped a notification or one of its action buttons. |
| `permission` | The notification permission changed, after an ask or when the app comes back to the foreground. |
| `received` | A remote push arrived while the app is running. |
| `reply` | A reply typed into a rich notification was sent to the reply endpoint. |
| `token` | A push token arrived or changed, on registration and again on each launch. Upload it to your server each time. |

## Configuration

Set these in the package settings of your app (see [Add a package](/packages/add-a-package)).

| Setting | What it is |
| :-- | :-- |
| Communication notifications (sender name and avatar) (`communication_notifications`) | Show pushes that carry a sender as communication notifications, with the sender's name and avatar. Turn on only when the app sends messages from people and the Communication Notifications capability is enabled on its App ID. |
| Default channel description (`default_channel_description`) | The sentence under the channel name in Android's notification settings. |
| Default Android channel id (`default_channel_id`) | The channel a notification lands in when the caller names none. Android 8 and above require every notification to have one. |
| Default channel importance (`default_channel_importance`) | How loud the default channel is: none, min, low, default, high or max. |
| Default channel name (`default_channel_name`) | What the user sees for the default channel in Android's notification settings. Write the category, not the app name. |
| Use exact alarms on Android (`exact_alarms`) | Ask AlarmManager for exact delivery when the user has granted the exact-alarm permission. Off means scheduled notifications may be delivered a few minutes late while the device is idle. |
| Foreground presentation (`foreground_presentation`) | What a notification does when it lands while the app is already open: any of alert, sound, badge and list, comma separated. Empty means nothing is shown. |
| Notification sounds (`sounds`) | The package resources a notification may play, as &lt;package&gt;/&lt;path&gt;, e.g. app/sounds/chime.wav. |
| Push transport (`token_kind`) | Which remote-push transport the token action asks for: auto, apns or fcm. |

## What you need on your side

- Local notifications need nothing else.
- For remote pushes without a push service, your server sends them to Apple (APNs) and Google (FCM) with the token from the `notify.token` broadcast. Or use [OneSignal](/packages/onesignal), [Pushwoosh](/packages/pushwoosh) or [Firebase](/packages/firebase).

Despia never hosts your app, your backend or your users' content: the accounts and servers above are your own.

For apps built on Despia V3, see [Migrate from Despia V3](/packages/migrate-from-v3).
