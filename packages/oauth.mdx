<Info>Modern API. Requires Despia V4 or greater. Despia V4 is currently a pre-release (0.0.2), stable for web view apps. Check for it first, see [Detect Despia V4](/packages/overview#detect-despia-v4).</Info>

Opens your provider's sign-in page in the trusted system browser sheet and hands you back every value the provider sent to your redirect address, such as the code or the tokens. It checks the state value for you and can create and redeem a PKCE challenge. You write the authorize address and exchange the code with your own backend or the provider.

**When to use it.** Use it for social or enterprise sign-in with providers that refuse to load inside an embedded web view. If you only need a native Apple or Google button, use that provider's own package instead.

<EnvNew />

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `oauth` package is on the global `window.dsx`. `dsx.has('oauth')` is true when the package is in your app's build:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('oauth')) {
  // Opens the provider's authorize address in the system sign-in sheet and waits for the user to finish. You get back the redirect address and every parameter it carried, or a clear refusal such as cancelled.
  const startResult = await dsx.module.oauth.start({ url: "https://idp.example/authorize?client_id=app&state=s1" })

  // Tells you whether this device can return a sign-in through your own https host and through the custom URL scheme right now.
  const capabilities = await dsx.module.oauth.capabilities()

  // Swaps an authorization code for tokens at your token endpoint, using the PKCE verifier created by a start or session call with pkce set. The verifier is only ever sent to an address you listed in the token endpoints setting.
  const exchange = await dsx.module.oauth.exchange()
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

## Action reference

<AccordionGroup>
<Accordion title="capabilities">

Tells you whether this device can return a sign-in through your own https host and through the custom URL scheme right now.

**Arguments:** none.

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `customScheme` | boolean | True when the app has a custom URL scheme set up for sign-in returns. |
| `httpsCallback` | boolean | True when this device can return a sign-in through your own https host. |

</Accordion>
<Accordion title="exchange">

Swaps an authorization code for tokens at your token endpoint, using the PKCE verifier created by a start or session call with pkce set. The verifier is only ever sent to an address you listed in the token endpoints setting.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `client_id`? | string | Your client id at the provider, if it expects one. |
| `code` | string | The authorization code returned by start. |
| `redirect_uri`? | string | The redirect address used in the authorize request, if the provider expects it again. |
| `token_url` | string | The https address of the provider's token endpoint; it must be listed in the token endpoints setting. |

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `access_token`? | string | The access token issued by the provider. |
| `expires_in`? | number | How many seconds the access token stays valid. |
| `id_token`? | string | The signed identity token, when the provider issues one. |
| `refresh_token`? | string | A token you can use to get a new access token, when the provider issues one. |
| `scope`? | string | The permissions the provider actually granted. |
| `token_type`? | string | The kind of token, usually Bearer. |

**Errors**

| Code | Message |
| :-- | :-- |
| `auth_failed` | The token exchange did not complete. |
| `missing_param` | A required parameter is missing. |
| `not_configured` | The token URL is not an https origin listed in token_endpoints. |
| `pkce_unsupported` | No PKCE verifier is held for this exchange. |

</Accordion>
<Accordion title="session">

Runs the same sign-in sheet as start but hands back only the raw redirect address, for packages that read the callback themselves.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `ephemeral`? | boolean | Set true to run the sheet without the browser's saved sessions. |
| `host`? | string | An https domain to return through instead of the custom scheme; iOS 17.4 and later only. |
| `path`? | string | The path prefix of the https callback when you use host. |
| `pkce`? | boolean | Set true to create a PKCE challenge you can redeem with exchange. |
| `proofs`? | boolean | Set true to attach the proof checks the calling package needs. |
| `url` | string | The full authorize address of the provider. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.oauth.session({ url: "https://idp.example/authorize?client_id=app&state=s1" })
```

```json Result
{
  "url": "myapp://oauth?code=abc&state=s1"
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `url` | string | The full redirect address the provider sent the user to. |

**Errors**

| Code | Message |
| :-- | :-- |
| `auth_failed` | Sign-in did not complete. |
| `blocked` | The browser blocked the sign-in window. Start sign-in from a tap. |
| `cancelled` | Sign-in was cancelled. |
| `missing_param` | A required parameter is missing. |
| `nonce_mismatch` | The sign-in response did not match this request. |
| `not_configured` | No app callback URL scheme is configured. |
| `state_mismatch` | The sign-in response did not belong to this sign-in request. |

</Accordion>
<Accordion title="start">

Opens the provider's authorize address in the system sign-in sheet and waits for the user to finish. You get back the redirect address and every parameter it carried, or a clear refusal such as cancelled.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `callback`? | string | Set to https to return through your own https host instead of the custom URL scheme. |
| `ephemeral`? | boolean | Set true to run the sheet without the browser's saved sessions, so the user always signs in fresh. |
| `host`? | string | An https domain to return through instead of the custom scheme; iOS 17.4 and later only. |
| `path`? | string | The path prefix of the https callback when you use host; defaults to /. |
| `pkce`? | boolean | Set true to create a PKCE challenge now and redeem it later with exchange. |
| `url` | string | The full authorize address of your provider, including client id and redirect address. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.oauth.start({ url: "https://idp.example/authorize?client_id=app&state=s1" })
```

```json Result
{
  "params": {
    "code": "abc",
    "state": "s1"
  },
  "url": "myapp://oauth?code=abc&state=s1"
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `params` | object | Every query and fragment parameter of that address, by name, such as code, state or access_token. |
| `url` | string | The full redirect address the provider sent the user to. |

**Errors**

| Code | Message |
| :-- | :-- |
| `auth_failed` | Sign-in did not complete. |
| `blocked` | The browser blocked the sign-in window. Start sign-in from a tap. |
| `cancelled` | Sign-in was cancelled. |
| `missing_param` | A required parameter is missing. |
| `nonce_mismatch` | The sign-in response did not match this request. |
| `state_mismatch` | The sign-in response did not belong to this sign-in request. |

</Accordion>

## Broadcasts

Listen with `window.dsx.module.oauth.on('<broadcast>', (data) => { ... })`. It returns a function that stops listening.

| Broadcast | When it fires |
| :-- | :-- |
| `error` | A sign-in could not complete because the callback host is not linked to the app; its fields say which host and which system code. |

## Configuration

Set these in the package settings of your app (see [Add a package](/packages/add-a-package)).

| Setting | What it is |
| :-- | :-- |
| HTTPS callback path (Android) (`app_link_paths`) | The path your provider redirects to, so the sign-in return keeps working when Android App Links are narrowed. |
| Native Sign in with Apple (`native_apple_signin`) | Open the native Apple sheet when the page calls the Apple JS SDK with usePopup: true. |
| Extra origins for native Apple sign-in (`native_apple_signin_origins`) | Additional https origins of your own that may use the native Apple sheet. |
| Token endpoints allowed to receive the PKCE verifier (`token_endpoints`) | The https origins this app may redeem an authorization code at, for example https://oauth2.googleapis.com. Leave it empty if the app does not use device-held PKCE. |

## What you need on your side

- An app registered with each sign-in provider (Google, Apple and so on), with your redirect address.
- If the app redeems the authorization code itself, list the provider's token origin under **token endpoints**; otherwise your backend exchanges the code.

Despia never hosts your app, your backend or your users' content: the accounts and servers above are your own.

For apps built on Despia V3, see [Migrate from Despia V3](/packages/migrate-from-v3).
