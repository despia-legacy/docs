<Info>
  The Modern API requires **Despia V4 or greater**. Despia V4 is currently a **pre-release (0.1.0)**, stable for web view (hybrid) apps. For apps built on Despia V3, see [Migrate from Despia V3](/packages/migrate-from-v3).

<Note>
  These pages cover **web view (hybrid) apps**: your web app runs inside the Despia app and calls native features from JavaScript. Native UI apps are coming soon.
</Note>

Every Despia V4 app puts one global object on the page: `window.dsx`. Every package in your app is reachable from it with the same dot notation:

```javascript
const dsx = window.dsx
if (dsx) {
  await dsx.module.haptic.light()
  const purchase = await dsx.module.revenuecat.purchase({ product: ["coins_100"] })
}
```

There is nothing to install. The global is there before your first script runs, so it works the same from plain JavaScript, React, Vue, Svelte, Next.js or any other framework.

## Detect Despia V4

`window.dsx` exists only inside a Despia V4 app, where the runtime installs it before your first script runs. In a normal browser it is `undefined`. Despia code runs in the browser (the app's web view), never on a server.

**The rule:** check `window.dsx`, then call through it:

```javascript
if (window.dsx) {
  await window.dsx.module.haptic.success()
} else {
  // normal browser
}
```

In frameworks that render on the server, do this in an effect or event handler, which only run in the browser (see [Frameworks](/packages/frameworks/overview)).

### Check that a package is in the app

An app only contains the packages you added to it (see [Add a package](/packages/add-a-package)). Ask before calling an optional package:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('revenuecat')) {
  // RevenueCat is in this build
}
```

| Check | Answers |
| :-- | :-- |
| `dsx.has('revenuecat')` | `true` when the package is in this build. Takes the package name or its scheme, case-insensitive. |
| `dsx.module.revenuecat.available` | The same answer, read from the package itself. |
| `dsx.version('revenuecat')` | The package version in this build, or `null`. |
| `dsx.packages` | Every package in this build, as a list of `{ name, version, scheme }`. |
| `dsx.wasExcluded('revenuecat')` | `true` when the app excluded the package on purpose. |

<Warning>
  Do not test `if (dsx.module.revenuecat)`. Any name under `dsx.module` gives back a callable value, so that check is always true. Use `dsx.has()` or `.available`.
</Warning>

## Calling convention

In the examples below, `dsx` is the value read with the rule above. Every call has the shape `dsx.module.<package>.<action>(args)`. `args` is one plain object. Actions with a dot in their name are written as a chain, for example `dsx.module.notify.permission.request()`.

There are three kinds of call:

<CodeGroup>

```javascript Fire and forget
dsx.module.haptic.light()
```

```javascript Resolve once
const info = await dsx.module.device.info()
```

```javascript Stream
const sub = dsx.module.speechrecognition.start({ interim: true }, (event) => {
  console.log(event.event, event.data)
})
// later
sub.stop()
```

</CodeGroup>

- **Resolve once.** The call returns a promise with the result.
- **Stream.** Pass a handler as the second argument. It is called for every update with an object that carries `event` (the update's name), `data` and `final`. The call returns an object with `stop()`.
- **Files.** A `File` or `Blob` you pass in an argument is uploaded for you and travels to the native side as a URL.

Each package page lists its actions, their arguments and what they return. The full list is in the sidebar under **Packages**.

### Errors

A failed call rejects its promise with an error object. Branch on its `code`:

```javascript
try {
  await dsx.module.revenuecat.purchase({ product: ["coins_100"] })
} catch (err) {
  if (err.code === 'not_ready') {
    // RevenueCat is still starting up: try again in a moment
  } else {
    console.warn(err.code, err.message)
  }
}
```

The codes each action can return are listed in the package's own reference. A call that gets no answer rejects with the code `timeout`.

### Broadcasts

Packages also send broadcasts that are not the answer to a call, for example when a purchase changes the customer's entitlements. Listen on the package:

```javascript
const off = dsx.module.revenuecat.on('customerInfo', (data) => { /* ... */ })
off()  // stop listening
```

`dsx.module.<package>.on(handler)` without a broadcast name, and `dsx.on('<package>', handler)`, receive every broadcast of the package as the whole envelope. See [Broadcasts](/packages/broadcasts).

## What changed in Despia V4

- **The local server is HTTPS only.** Apps that serve their web build from the device do so over HTTPS.
- **Accessibility uses ARIA.** Write standard `aria-*` and `role` attributes. The older `a11y*` attributes are still read until 1.0.0.
