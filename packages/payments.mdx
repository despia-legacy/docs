Gives your app one way to start a payment, manage saved cards, link a bank account and open a customer portal, drawn by the payment package you add, such as Stripe. Add the provider packages you need and nothing more. Needs an account with that provider.

**When to use it.** Use it to take payments inside your app through one set of calls, whichever provider package you add. Choose it before wiring a provider's own calls, so you can change provider later. Do not use it for in-app purchases of digital goods, which belong to the stores.

<EnvNew />

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `payments` package is on the global `window.dsx`. `dsx.has('payments')` is true when the package is in your app's build:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('payments')) {
  // Shows the provider's payment sheet so the user can pick a method and pay, and returns when they finish or cancel.
  const payment = await dsx.module.payments.payment({ payment_intent_client_secret: "pi_123_secret_abc", publishable_key: "pk_test_123" })

  // Shows the sheet where the user manages their saved payment methods, adding or removing cards.
  const manage = await dsx.module.payments.manage({ customer_id: "cus_123", ephemeral_key_secret: "ek_123", publishable_key: "pk_test_123" })

  // Opens the bank-linking flow so the user can connect a bank account for later debits.
  const connectBank = await dsx.module.payments.connectBank({ financial_connections_session_client_secret: "fcsess_secret_abc", publishable_key: "pk_test_123" })
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

## Action reference

<AccordionGroup>
<Accordion title="close">

Abandons the open payment session and clears its state. Call it when the user leaves checkout without paying.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `session`? | string | The id of the open payment session this call applies to. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.payments.close()
```

```json Result
{
  "status": "canceled"
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `status` | string | How the payment ended, for example completed, canceled or failed. |

**Errors**

| Code | Message |
| :-- | :-- |
| `not_configured` | No payment processor serves this build: add a processor package (payments.stripe) or set the payments `processor` config. |
| `not_ready` | No Stripe session is open. |
| `settled` | This session is finished. Open a new one to take another payment. |

</Accordion>
<Accordion title="confirm">

Confirms the payment in the open session using the part of the screen the user acted on.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `session`? | string | The id of the open payment session this call applies to. |
| `view`? | "inline" \\| "overlay" \\| "wallet" | Which part of the screen is confirming: inline (the card field), overlay (the payment sheet) or wallet (Apple Pay or Google Pay). |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.payments.confirm()
```

```json Result
{
  "method": "cardInput",
  "status": "completed"
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `code`? | string | A short code for the failure, when there was one. |
| `error`? | string | A readable reason, when the payment did not succeed. |
| `method` | string | The payment method the user paid with, such as card or Apple Pay. |
| `status` | string | How the payment ended, for example completed, canceled or failed. |

**Errors**

| Code | Message |
| :-- | :-- |
| `busy` | A payment is already being confirmed. |
| `detached_view` | That face is not attached to this session. |
| `not_configured` | No payment processor serves this build: add a processor package (payments.stripe) or set the payments `processor` config. |
| `not_confirming` | No payment is being confirmed. |
| `not_ready` | No Stripe session is open. |
| `settled` | This session is finished. Open a new one to take another payment. |

</Accordion>

## Configuration

Set these in the package settings of your app (see [Add a package](/packages/add-a-package)).

| Setting | What it is |
| :-- | :-- |
| Payment processor (retired) (`processor`) | Retired spelling of `provider`; still read as the same choice. Set `provider` instead. |
| Payment provider (`provider`) | Optional: which provider package takes payments (for example stripe). Empty means the one provider package this app includes. |

## What you need on your side

- An account with your payment provider (for example Stripe) and your own backend.
- Your backend creates the payment objects and hands the page their client secrets (`payment_intent_client_secret`, `setup_intent_client_secret`, `ephemeral_key_secret`) and the provider's publishable key. The secret API key stays on your server and never goes into the app.

Despia never hosts your app, your backend or your users' content: the accounts and servers above are your own.

For apps built on Despia V3, see [Migrate from Despia V3](/packages/migrate-from-v3).
