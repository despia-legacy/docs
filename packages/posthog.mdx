Works with the Product analytics package: it takes the events it collects and delivers them to your PostHog project. PostHog accepts events without confirming it kept them, so check its activity view when you first connect. Needs a PostHog account and your project key.

**When to use it.** Use it when you analyse your product in PostHog. It sends the events your app already records to your PostHog project; you do not call it yourself.

<EnvNew />

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `posthog` package is on the global `window.dsx`. `dsx.has('posthog')` is true when the package is in your app's build:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('posthog')) {
  // Sends a batch of recorded events to your PostHog project in one request. The product analytics package calls it for you.
  const send = await dsx.module.posthog.send({ events: [{"anonymousId": "a-1", "at": 1758801600000, "event": "checkout.started", "eventId": "e-1", "platform": "ios", "properties": {}, "sessionId": "s-1", "source": "app"}], token: "phc_abcdefghijklmnopqrstuvwxyz0123456789ABCDEFG" })
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

| Call | Arguments | Returns | Platforms | What it does |
| :-- | :-- | :-- | :-- | :-- |
| `dsx.module.posthog.send()` | `endpoint`?: string<br/>`events`: object[]<br/>`token`: string | `confirmed`<br/>`sent` | iOS, Android | Sends a batch of recorded events to your PostHog project in one request. The product analytics package calls it for you. |

## Action reference

<AccordionGroup>
<Accordion title="send">

Sends a batch of recorded events to your PostHog project in one request. The product analytics package calls it for you.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `endpoint`? | string | The PostHog address to send to, such as the EU cloud, your own server or a proxy; defaults to the US cloud. |
| `events` | object[] | The batch of events to send, each with its id, name, properties and time. |
| `token` | string | Your PostHog project token, which starts with phc_ and is safe to ship in an app. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.posthog.send({ events: [{"anonymousId": "a-1", "at": 1758801600000, "event": "checkout.started", "eventId": "e-1", "platform": "ios", "properties": {}, "sessionId": "s-1", "source": "app"}], token: "phc_abcdefghijklmnopqrstuvwxyz0123456789ABCDEFG" })
```

```json Result
{
  "confirmed": false,
  "sent": 1
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `confirmed`? | boolean | Always false: PostHog accepted the request but that is not a delivery receipt. |
| `sent` | number | How many events were sent in the batch. |

**Errors**

| Code | Message |
| :-- | :-- |
| `destination_unavailable` | PostHog could not be reached. |
| `invalid_endpoint` | The PostHog endpoint must be https, or http to a local development host. |
| `invalid_token` | That is not a PostHog project token (phc_ plus 20 to 64 letters and digits). |
| `rejected` | PostHog refused the batch. |

</Accordion>
</AccordionGroup>

## What you need on your side

- A PostHog project. `send()` takes its project token (the public key PostHog gives you for client apps).

Despia never hosts your app, your backend or your users' content: the accounts and servers above are your own.
