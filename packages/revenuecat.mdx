<Info>Modern API. Requires Despia V4 or greater. Despia V4 is currently a pre-release (0.0.2), stable for web view apps. Check for it first, see [Detect Despia V4](/packages/overview#detect-despia-v4).</Info>

Lets your pages start a purchase, open a RevenueCat paywall or the customer center, and read products, offerings, purchase history and what a user is entitled to. Use it when your team already manages subscriptions in RevenueCat. Needs a RevenueCat account and its iOS and Android API keys.

**When to use it.** Reach for it when your subscriptions and in-app purchases are managed in RevenueCat and you want one call to sell, show a paywall and check what a person owns. Do not include it next to the standalone RevenueCat package, since an app uses one or the other.

<EnvNew />

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `revenuecat` package is on the global `window.dsx`. `dsx.has('revenuecat')` is true when the package is in your app's build:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('revenuecat')) {
  // Buys a product through the store's payment sheet and tells you what the person owns afterwards. It tries the products you list in order and stops at the first one the store returns.
  const purchase = await dsx.module.revenuecat.purchase({ external_id: "user_123", product: ["coins_100:monthly"] })

  // Shows a RevenueCat paywall sheet for an offering so the person can pick and buy.
  const paywall = await dsx.module.revenuecat.paywall({ external_id: "user_123" })

  // Returns the person's entitlements, subscriptions and management link in one shared envelope, and also broadcasts it as customer.
  const customer = await dsx.module.revenuecat.customer()
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

<Accordion title="buy">

Buys a package on the open session from your own paywall button, and settles the same way the overlay paywall does. A second buy while one is running is refused.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `package`? | string | The package to buy. Defaults to the one currently selected in the session. |
| `view`? | string | The id of the paywall face that is attaching to or detaching from the open session. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.revenuecat.buy({ package: "annual" })
```

```json Result
{
  "package": "annual",
  "status": "completed"
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `package` | string | The package that was bought. |
| `status` | string | A short word saying how the purchase ended, such as purchased or failed. |

**Errors**

| Code | Message |
| :-- | :-- |
| `busy` | A purchase is already being made. |
| `detached_view` | That face is not attached to this session. |
| `not_ready` | RevenueCat is still starting up. Please try again in a moment. |
| `settled` | This paywall session is finished. Open a new one to buy again. |
| `unsupported_platform` | RevenueCat store purchases are not available on the web. |

</Accordion>
<Accordion title="catalog">

Returns the products, offerings and prices in one shared envelope that is identical on iOS and Android, and also broadcasts it as products.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `external_id`? | string | Your own id for the signed-in person. Leave it out to act as the current, possibly anonymous, RevenueCat user. |
| `offering`? | string | The id of the RevenueCat offering to use. When omitted or unknown, the current offering is used. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.revenuecat.catalog()
```

```json Result
{
  "offerings": [],
  "ok": true,
  "platform": "ios",
  "products": [],
  "provider": "revenuecat",
  "runtime": 4
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `code`? | string | A short error code, set only when the envelope reports a failure. |
| `current`? | string | The id of the current offering. |
| `offerings` | object[] | Every offering with its packages. |
| `ok` | boolean | True when the call succeeded and the envelope carries real data. |
| `platform` | string | The platform that answered, such as ios or android. |
| `products` | object[] | Every product with its store title and price. |
| `provider` | string | The name of the billing provider that answered, which is revenuecat. |
| `runtime` | number | The version of the shared response envelope, the same on iOS and Android. |

**Errors**

| Code | Message |
| :-- | :-- |
| `network_unavailable` | RevenueCat could not be reached. Your purchases are safe; try again when you are back online. |
| `not_ready` | RevenueCat is still starting up. Please try again in a moment. |
| `offerings_failed` | Could not load the available offerings. |

## Broadcasts

Listen with `window.dsx.module.revenuecat.on('<broadcast>', (data) => { ... })`. It returns a function that stops listening.

| Broadcast | When it fires |
| :-- | :-- |
| `center` | Fires when the customer center is closed or the person acts in it. |
| `customerInfo` | Fires after every purchase, restore, sign-in or SDK update with the person's RevenueCat customer record. |
| `session.changed` | Fires when the paywall session moves to a new state. |
| `session.settled` | Fires when the paywall session ends, by a purchase, a failure or a cancel. |

## Configuration

Set these in the package settings of your app (see [Add a package](/packages/add-a-package)).

| Setting | What it is |
| :-- | :-- |
| Android API key (`androidApiKey`) | Your RevenueCat public Google Play API key. |
| API key (`apiKey`) | Your RevenueCat public API key. |
| Project ID (`projectId`) | Your RevenueCat project id, used by the page side and not needed by the SDK. |

## What you need on your side

- A RevenueCat project with your iOS and Android apps, and your products set up in App Store Connect and Google Play Console.
- RevenueCat's public SDK keys in the package settings: **API key** (`appl_...`) and **Android API key** (`goog_...`). These keys are meant to ship in apps.
- Optional: RevenueCat [webhooks](https://www.revenuecat.com/docs/integrations/webhooks) to your own backend, if your server needs to know about purchases and entitlements.

Despia never hosts your app, your backend or your users' content: the accounts and servers above are your own.

For apps built on Despia V3, see [Migrate from Despia V3](/packages/migrate-from-v3).
