<Info>Modern API. Requires Despia V4 or greater. Despia V4 is currently a pre-release (0.1.0), stable for web view apps. Check for it first, see [Detect Despia V4](/packages/overview#detect-despia-v4).</Info>

A simple store for things like a theme choice, a language or a last-seen date. Values keep their type: a number comes back a number. Read or write one value or many at once in a single call, list keys by prefix a page at a time, and every change is announced so two screens never disagree. Values stay on the device, with no account or keys needed.

**When to use it.** Reach for it to remember small things between launches, such as a theme, a language or the last screen. It is not meant for large files or secrets; use files for big data and a secure store for credentials.

<EnvNew />

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `storage` package is on the global `window.dsx`. `dsx.has('storage')` is true when the package is in your app's build:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('storage')) {
  // Saves one value under a key. Strings, numbers, true or false, null, lists and objects are all kept with their type.
  const setResult = await dsx.module.storage.set({ key: "theme", value: "dark" })

  // Reads one saved value by its key, with its original type, and says whether the key was found.
  const getResult = await dsx.module.storage.get({ key: "theme" })

  // Deletes every key in this app's store and says how many were removed.
  const clear = await dsx.module.storage.clear()
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

## Actions

| Call | Arguments | Returns | Platforms | What it does |
| :-- | :-- | :-- | :-- | :-- |
| `dsx.module.storage.clear()` | none | `ok`<br/>`removed` | iOS, Android | Deletes every key in this app's store and says how many were removed. |
| `dsx.module.storage.get()` | `key`: string | `found`<br/>`value` | iOS, Android | Reads one saved value by its key, with its original type, and says whether the key was found. |
| `dsx.module.storage.list()` | `after`?: string<br/>`end`?: string<br/>`limit`?: number<br/>`prefix`?: string<br/>`reverse`?: boolean<br/>`start`?: string<br/>`values`?: boolean | `cursor`<br/>`items`<br/>`more` | iOS, Android | Returns one page of saved keys, optionally filtered by prefix or range and optionally with their values. |
| `dsx.module.storage.multiGet()` | `keys`: string[] | `found`<br/>`values` | iOS, Android | Reads several keys in one call. Keys that are not saved are left out of the answer. |
| `dsx.module.storage.multiRemove()` | `keys`: string[] | `ok`<br/>`removed` | iOS, Android | Deletes several keys in one call, written together. Keys that are not there are ignored. |
| `dsx.module.storage.multiSet()` | `values`: object | `ok`<br/>`written` | iOS, Android | Saves several values in one call, written together. |
| `dsx.module.storage.open()` | none | `from`<br/>`migrated`<br/>`version` | iOS, Android | Brings the store up to the version your app declares by running your declared upgrade steps, and refuses a store written by a newer app. |
| `dsx.module.storage.remove()` | `key`: string | `ok` | iOS, Android | Deletes one saved key. Removing a key that is not there does nothing. |
| `dsx.module.storage.set()` | `key`: string<br/>`value`: any | `ok` | iOS, Android | Saves one value under a key. Strings, numbers, true or false, null, lists and objects are all kept with their type. |

## Action reference

<AccordionGroup>
<Accordion title="clear">

Deletes every key in this app's store and says how many were removed.

**Arguments:** none.

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.storage.clear()
```

```json Result
{
  "ok": true,
  "removed": 2
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `ok` | boolean | True when the change was made. |
| `removed` | number | How many keys were actually deleted. |

**Errors**

| Code | Message |
| :-- | :-- |
| `app_identity_missing` | Configure a stable DSX desktop app id before using persistent values. |
| `persistence_unavailable` | The app-scoped desktop value store is unavailable. |
| `storage_unavailable` | The key/value store is not available on this device yet. |
| `value_too_large` | The value exceeds the desktop store's UTF-8 byte limit. |

</Accordion>
<Accordion title="get">

Reads one saved value by its key, with its original type, and says whether the key was found.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `key` | string | The name the value is saved under; it must be a non-empty string. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.storage.get({ key: "theme" })
```

```json Result
{
  "found": true,
  "value": "dark"
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `found` | boolean | True when the key is saved, which tells a saved null from a missing key. For multiGet, the number of keys found. |
| `value` | any | The saved value with its original type, or null when the key is not saved. |

**Errors**

| Code | Message |
| :-- | :-- |
| `app_identity_missing` | Configure a stable DSX desktop app id before using persistent values. |
| `invalid_key` | key must be a non-empty string. |
| `persistence_unavailable` | The app-scoped desktop value store is unavailable. |
| `storage_unavailable` | The key/value store is not available on this device yet. |

</Accordion>
<Accordion title="list">

Returns one page of saved keys, optionally filtered by prefix or range and optionally with their values.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `after`? | string | The cursor from the previous page, to continue after it. |
| `end`? | string | Only return keys before this one, alphabetically (exclusive). |
| `limit`? | number | How many keys to return at most; the default is 100 and the largest is 1000. |
| `prefix`? | string | Only return keys that start with this text. |
| `reverse`? | boolean | Set to true to walk the keys from last to first. |
| `start`? | string | Only return keys from this one onward, alphabetically (inclusive). |
| `values`? | boolean | Set to true to include each key's value in the results. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.storage.list({ prefix: "draft." })
```

```json Result
{
  "cursor": "",
  "items": [
    {
      "key": "draft.1"
    },
    {
      "key": "draft.2"
    }
  ],
  "more": false
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `cursor` | string | Pass this back as after to get the next page. |
| `items` | object[] | The keys in this page, each with its key and, if asked for, its value. |
| `more` | boolean | True when there are more keys after this page. |

**Errors**

| Code | Message |
| :-- | :-- |
| `app_identity_missing` | Configure a stable DSX desktop app id before using persistent values. |
| `invalid_query` | prefix, start, end and after must be strings, reverse and values booleans, and limit a whole number of at least 1. |
| `persistence_unavailable` | The app-scoped desktop value store is unavailable. |
| `storage_unavailable` | The key/value store is not available on this device yet. |

</Accordion>

<Accordion title="open">

Brings the store up to the version your app declares by running your declared upgrade steps, and refuses a store written by a newer app.

**Arguments:** none.

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.storage.open()
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `from` | number | The storage version the store was at before. |
| `migrated` | number | How many upgrade steps were run. |
| `version` | number | The storage version the store is now at. |

**Errors**

| Code | Message |
| :-- | :-- |
| `app_identity_missing` | Configure a stable DSX desktop app id before using persistent values. |
| `persistence_unavailable` | The app-scoped desktop value store is unavailable. |
| `storage_unavailable` | The key/value store is not available on this device yet. |
| `store_ahead` | The stored data was written by a NEWER version of this app. There is no migration backwards, so nothing was read. |
| `store_declaration_invalid` | The app's `storage` declaration does not parse, so the stored data was not opened. |
| `store_migration_missing` | The app declares no migration for every version between the stored data and its own. Nothing was read. |
| `store_unreadable` | The stored data carries a storage version this app cannot read. Nothing was read. |
| `value_too_large` | The value exceeds the desktop store's UTF-8 byte limit. |

</Accordion>

## Broadcasts

Listen with `window.dsx.module.storage.on('<broadcast>', (data) => { ... })`. It returns a function that stops listening.

| Broadcast | When it fires |
| :-- | :-- |
| `change` | Sent after any write to the store: set, remove, clear, their multi versions, and an open that upgraded the store. |

For apps built on Despia V3, see [Migrate from Despia V3](/packages/migrate-from-v3).
