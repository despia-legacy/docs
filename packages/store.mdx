<Info>Modern API. Requires Despia V4 or greater. Despia V4 is currently a pre-release (0.0.2), stable for web view apps. Check for it first, see [Detect Despia V4](/packages/overview#detect-despia-v4).</Info>

Shows a paywall you design in JSON, runs checkout, restores purchases and tells you which entitlements a user has, in the same shape on every platform. It works through Apple StoreKit 2 or RevenueCat. Use it for subscriptions, one-time purchases and paid features. Needs products set up in the App Store or Google Play, or a RevenueCat account.

**When to use it.** Reach for it when your app sells subscriptions or one-off purchases and you want one set of calls for paywall, checkout, restore and what a person owns, on both iOS and Android. If you already run everything in RevenueCat you can pick that as the provider and keep the same calls.

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `store` package is on the global `window.dsx`. `dsx.has('store')` is true when the package is in your app's build:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('store')) {
  // Reads which country's store the person is using, as a country code.
  const storefront = await dsx.module.store.storefront()

  // Opens the store's own screen for managing subscriptions, where the person can cancel or change plan.
  const manage = await dsx.module.store.manage()

  // Shows Google Play's own in-app message about a billing problem, such as a declined card during a grace period, so the person can fix it without leaving the app.
  const billingMessages = await dsx.module.store.billingMessages()
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

<AccordionGroup>
<Accordion title="billingMessages">

Shows Google Play's own in-app message about a billing problem, such as a declined card during a grace period, so the person can fix it without leaving the app.

**Arguments:** none.

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.store.billingMessages()
```

```json Result

  "outcome": "no_action_needed",
  "purchaseToken": ""
}
```

| Field | Type | Description |
| :-- | :-- | :-- |

| :-- | :-- |

<Accordion title="checkout">

Starts the store payment sheet for one product and resolves with the outcome and the transaction.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `appAccountToken`? | string | A UUID you choose that the store attaches to the transaction so your server can match it to an account. |
| `coins`? | boolean | Set it to true when the product is a coin pack. |
| `externalId`? | string | Your own id for the signed-in person, so the purchase belongs to your account. |
| `kind`? | string | Whether you are buying a plan or a coin pack. |
| `offer`? | string | The offer to buy: an offer id, basePlan:offerId on Google Play, or a Play offer token. Leave it out to take the first offer the store lists. |
| `offerSignature`? | object | For an iOS promotional offer, the signature your server made, so the signing key never ships in the app. |
| `product` | string | The store product id to buy. |
| `provider`? | string | Which provider answers, such as store or revenuecat. Leave it out to use the provider this app has set. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.store.checkout({ product: "pro_monthly", provider: "store" })
```

```json Result
{
  "outcome": "purchased",
  "product": "pro_monthly"
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `entitlements`? | string[] | The entitlements the person holds after the purchase. |
| `kind`? | string | Whether it was a coin pack or a plan. Present only after a purchase. |
| `outcome` | string | How checkout ended: purchased, pending, busy or failed. |
| `platform`? | string | Which platform it ran on, ios or android. |
| `product` | string | The product id that was bought. |
| `provider`? | string | Which provider ran the purchase: storekit, play_store or revenuecat. |
| `raw`? | object | The untouched provider response, present when RevenueCat is the provider. |
| `transaction`? | object | The normalized store transaction for the purchase. |

**Errors**

| Code | Message |
| :-- | :-- |
| `cancelled` | Purchase cancelled. |
| `missing_param` | A product id is required. |
| `network_unavailable` | The store could not be reached. Your purchases are safe; try again when you are back online. |
| `offer_signature_required` | A promotional offer needs a signature from your server. |
| `purchase_failed` | The purchase could not be completed. |
| `store_unavailable` | The store is not available on this device. |
| `unknown_offer` | That offer isn't available for this product. |
| `unsupported_provider` | Offers are bought through the store provider. |

<Accordion title="paywall">

Builds and shows a native paywall from a JSON description of products, features and coins, and resolves when the person buys, restores or closes it.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `accent`? | string | The accent colour used for buttons and highlights. |
| `actions`? | string[] | Names of your own actions the layout may fire, each sent back to you as an event of that name. |
| `appAccountToken`? | string | A UUID you choose that the store attaches to the transaction so your server can match it to an account. |
| `balance`? | number | The person's current coin balance, shown on a coin paywall. |
| `coins`? | object[] | The coin pack rows to show, each with a product id and a coin amount. |
| `countdown`? | number | A number of seconds for a countdown shown on the paywall. |
| `cta`? | string | The text on the main buy button. |
| `data`? | object | The whole paywall as one object. Any top-level paywall key here wins, and other keys become named state the layout can read. |
| `display`? | string | How the paywall is displayed on screen. |
| `entitlement`? | string | The entitlement the paywall is selling, used to check whether the person already has it. |
| `externalId`? | string | Your own id for the signed-in person, so the purchase belongs to your account. |
| `features`? | string[] | The feature lines listed on the paywall. |
| `footer`? | object | Content for the bottom of the paywall, such as links to terms. |
| `header`? | object | Content for the top of the paywall. |
| `mode`? | string | How the paywall is presented. |
| `products`? | object[] | The subscription or purchase rows to show, each with a store product id and a title. |
| `provider`? | string | Which provider answers, such as store or revenuecat. Leave it out to use the provider this app has set. |
| `restore`? | boolean | Set it to true to show a restore purchases button. |
| `subtitle`? | string | The line under the heading. |
| `template`? | string | The built-in paywall layout to use. |
| `theme`? | object | Colours and styling overrides for the paywall. |
| `title`? | string | The main heading of the paywall. |
| `token`? | string | A token passed through to the provider with the purchase. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.store.paywall({ externalId: "user_123", products: [{"price": "$9.99", "productId": "pro_monthly", "title": "Pro"}], provider: "revenuecat", template: "tiers" })
```

```json Result
{
  "entitlements": [],
  "outcome": "dismissed"
}
```

**Result:** a stream. Pass a handler as the second argument; it receives each update.

**Errors**

| Code | Message |
| :-- | :-- |
| `no_presenter` | Could not find a screen to present the purchase. |

```json Result
  "subscriptions": [],
  "willRenew": true
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `billingIssue` | boolean | True when the store is having trouble charging the person. |
| `gracePeriodEndsAt` | number | When the grace period ends, in milliseconds since 1970, or 0 when none applies. |
| `provider` | string | Which purchase provider answered the request. |
| `renewsAt` | number | When the next renewal is due, in milliseconds since 1970, or 0 when unknown. |
| `state` | string | The subscription state, such as active, grace period or expired. |
| `subscriptions` | object[] | Every active subscription with its own state and renewal time. |
| `willRenew` | boolean | True when the subscription will renew on its own. |

**Errors**

| Code | Message |
| :-- | :-- |
| `network_unavailable` | The store could not be reached. Your purchases are safe; try again when you are back online. |
| `store_unavailable` | The store is not available on this device. |

## Configuration

Set these in the package settings of your app (see [Add a package](/packages/add-a-package)).

| Setting | What it is |
| :-- | :-- |
| Purchase provider (`provider`) | Optional: which provider runs purchases and answers what a person owns (store, revenuecat or commerce). Empty means the one provider package this app includes, or the App Store and Google Play directly. |

## What you need on your side

- Products set up in App Store Connect and Google Play Console.
- The **provider** setting chooses who answers: `store` (the App Store and Google Play directly), `revenuecat` or `commerce`. With `revenuecat`, you also need what the [RevenueCat](/packages/revenuecat) page lists.
- If your server must check purchases itself, it talks to Apple's and Google's server APIs (or your provider's) with your own credentials.

Despia never hosts your app, your backend or your users' content: the accounts and servers above are your own.

For apps built on Despia V3, see [Migrate from Despia V3](/packages/migrate-from-v3).
