Connects Apple Health and wearables such as Fitbit, Garmin, Oura and Whoop through Terra, then syncs and reads the data. Needs a Terra account and developer ID, and your own server to start sessions with Terra's API. It is off by default and you turn it on when you want it.  ## How it connects  - **Apple Health** is read on the device through HealthKit. iOS asks the person once, with the purpose strings you set. - **Wearables** (Fitbit, Garmin, Oura, Whoop and more) connect through Terra's Connect widget, opened from your app. - **Your server** mints the session token with Terra's API, so your Terra API key never ships in the app.  ## Set it up  1. Create a developer account at [Terra](https://tryterra.co) and copy your developer ID. 2. Add **Terra Health** and set **Developer ID**. Leaving it empty keeps the integration off. 3. Write the **Health read prompt** iOS shows when it asks to read Health data. 4. Add a route on your server that asks Terra for a session token for the signed-in user.  \| Setting \| What it is \| \| --- \| --- \| \| Developer ID \| Your Terra developer ID \| \| Health read prompt \| The message iOS shows before reading Health data \| \| Health write prompt \| The message iOS shows before saving to Health \| 

**When to use it.** Add it when your app should read Apple Health or wearable data (Fitbit, Garmin, Oura, Whoop) and forward it to your own backend through Terra. It needs a Terra account; if you only want Apple Health data inside the app, use the HealthKit package.

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `terra` package is on the global `window.dsx`. `dsx.has('terra')` is true when the package is in your app's build:

```javascript
const dsx = window.dsx
if (dsx && dsx.has('terra')) {
  // Links Apple Health or a wearable provider to Terra for this person and starts the first sync.
  const connect = await dsx.module.terra.connect({ session: "https://widget.tryterra.co/session/abc", user_id: "ref_123" })

  // Sends the latest health data to your Terra destination now, without asking the person again.
  const sync = await dsx.module.terra.sync({ backfill_days: 7 })

  // Shows the system health data permission dialog when it can still be shown, and returns the resulting state.
  const permissionRequest = await dsx.module.terra.permission.request()
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

## Action reference

<AccordionGroup>
<Accordion title="connect">

Links Apple Health or a wearable provider to Terra for this person and starts the first sync.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `backfill_days`? | number | How many days of history to load when connecting; defaults to the last value, then 7. |
| `ignored_sources`? | string[] | App ids whose Apple Health data should be left out, for example to avoid duplicates with a wearable provider. |
| `session`? | string | A Terra token from your server for Apple Health, or a Connect widget address for other providers. |
| `user_id`? | string | Your own stable id for the person; Terra stores it as the reference id. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.terra.connect({ session: "https://widget.tryterra.co/session/abc", user_id: "ref_123" })
```

```json Result
{
  "provider": "fitbit",
  "via": "widget"
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `alreadyConnected`? | boolean | True when the source was already linked and was only resynced. |
| `params`? | object | Extra values the widget returned. |
| `provider` | string | The linked source, such as healthkit. |
| `referenceId`? | string | Your own id for the person, as stored in Terra. |
| `resource`? | string | The provider that was linked through the widget. |
| `userId`? | string | The Terra user id for the person. |
| `via`? | string | Set to widget when a provider was linked through the Connect widget. |

**Errors**

| Code | Message |
| :-- | :-- |
| `connect_failed` | The connection could not be completed. |
| `invalid_widget_url` | That is not a usable Terra Connect widget URL. |
| `missing_session` | A session token is required for a first-time connect. |
| `missing_user_id` | A user_id is required. |
| `not_configured` | Terra is not configured. Fill in the dev-id in this package's config.json. |
| `sdk_init_failed` | The Terra SDK could not start. |
| `widget_auth_failed` | The provider's sign-in sheet did not authenticate. |
| `widget_cancelled` | The sign-in sheet was dismissed before it finished. |

</Accordion>
<Accordion title="data">

Reads health data straight from the device for display in your app, without sending it to your destination.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `end`? | number | End of the window as a time in milliseconds; overrides query. |
| `query`? | string | The time window: daily (since the start of today), weekly (last 7 days) or hourly (last hour). |
| `resources`? | string[] | Which kinds of data to read, such as daily, activity, sleep, body, nutrition, menstruation or athlete. |
| `start`? | number | Start of the window as a time in milliseconds; overrides query. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.terra.data({ query: "daily", resources: ["daily", "sleep"] })
```

```json Result
{
  "query": "daily",
  "succeeded": [
    "daily"
  ]
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `endMs`? | int | End of the window as a time in milliseconds. |
| `failed`? | object[] | The data kinds that could not be read, each with the reason. |
| `query` | string | The window that was read. |
| `resources`? | string[] | The data kinds that were read. |
| `results`? | object | The data read, grouped by kind. |
| `startMs`? | int | Start of the window as a time in milliseconds. |
| `succeeded` | string[] | The data kinds that were read. |

**Errors**

| Code | Message |
| :-- | :-- |
| `not_configured` | Terra is not configured. Fill in the dev-id in this package's config.json. |
| `not_connected` | The health store is not connected yet. Call connect first. |
| `sdk_init_failed` | The Terra SDK could not start. |

</Accordion>

## Broadcasts

Listen with `window.dsx.module.terra.on('<broadcast>', (data) => { ... })`. It returns a function that stops listening.

| Broadcast | When it fires |
| :-- | :-- |
| `connected` | A source was linked; it carries the same values the connect call returns. |
| `disconnected` | The person was unlinked inside the app. |
| `ready` | Fires on every page load with the current connection state, so the page needs no setup call. |
| `sync_started` | A sync began, whether you asked for it or the app started it. |
| `synced` | A sync finished, with how it went. |

## Configuration

Set these in the package settings of your app (see [Add a package](/packages/add-a-package)).

| Setting | What it is |
| :-- | :-- |
| Developer ID (`devId`) | Your Terra developer ID; leave empty to keep the integration off. |
| Health read prompt (`usage_share_description`) | The message shown when iOS asks permission to read Health data. |
| Health write prompt (`usage_update_description`) | The message shown when iOS asks permission to save data to Health. |

## What you need on your side

- A Terra developer account: your **developer ID** in the package settings.
- Your server creates the Terra token that `terra.connect({ session })` needs; your Terra API key stays on your server.

Despia never hosts your app, your backend or your users' content: the accounts and servers above are your own.

For apps built on Despia V3, see [Migrate from Despia V3](/packages/migrate-from-v3).
