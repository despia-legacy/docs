<Info>Modern API. Requires Despia V4 or greater. Despia V4 is currently a pre-release (0.0.2), stable for web view apps. Check for it first, see [Detect Despia V4](/packages/overview#detect-despia-v4).</Info>

Opens named WebSocket connections, reconnects with a growing delay, and keeps outgoing and incoming messages in a durable queue so nothing is lost across a drop or a relaunch. You get connection state to show in your screens and an acknowledgement call to confirm each message. You write the messages your server expects.

**When to use it.** Reach for it when your app needs a live connection to your own server, such as chat, live feeds or presence, and messages must survive a dropped connection or a relaunch. For one-off requests use a normal API call instead.

## Call it from JavaScript

No npm package is needed. Inside a Despia V4 app, the `websocket` package is on the global `window.dsx` and is built into every app:

```javascript
// built into every Despia V4 app
const dsx = window.dsx
if (dsx) {
  // Opens a named connection to a ws:// or wss:// address, or updates it if it is already open, and reconnects automatically if it drops.
  const connect = await dsx.module.websocket.connect({ id: "feed", url: "wss://example.com/socket" })

  // Adds a text message to the outgoing queue. Messages survive a drop and a relaunch and are sent in order once the connection is open.
  const send = await dsx.module.websocket.send({ id: "feed", payload: "{\"op\":\"ping\"}" })

  // Stores one message that is sent first on every connect and reconnect, for example a login or channel-join frame. An empty frame clears it.
  const subscribe = await dsx.module.websocket.subscribe({ frame: "{\"op\":\"subscribe\",\"channel\":\"orders\"}", id: "feed" })
}
```

Calls that return something give you a promise; calls that stream take a handler as the second argument and return an object with `stop()`. Errors reject with an object that carries a `code`. See [Calling convention](/packages/overview#calling-convention).

## Actions

| Call | Arguments | Returns | Platforms | What it does |
| :-- | :-- | :-- | :-- | :-- |
| `dsx.module.websocket.ack()` | `id`: string<br/>`message_id`: string | `id`<br/>`message_id`<br/>`ok` | iOS, Android | Confirms that one received message was handled, so it is not delivered again. |
| `dsx.module.websocket.connect()` | `headers`?: object<br/>`id`: string<br/>`protocols`?: string<br/>`reconnect`?: boolean<br/>`url`: string | `id`<br/>`ok` | iOS, Android | Opens a named connection to a ws:// or wss:// address, or updates it if it is already open, and reconnects automatically if it drops. |
| `dsx.module.websocket.disconnect()` | `id`: string | `id`<br/>`ok` | iOS, Android | Closes the connection and stops it reconnecting. The queues are kept, so connecting again under the same id carries on where it left off. |
| `dsx.module.websocket.send()` | `id`: string<br/>`payload`: string | `id`<br/>`ok` | iOS, Android | Adds a text message to the outgoing queue. Messages survive a drop and a relaunch and are sent in order once the connection is open. |
| `dsx.module.websocket.status()` | `id`: string | `id`<br/>`ok`<br/>`pendingOutbound`<br/>`reconnectAttempt`<br/>`state`<br/>`unacked` | iOS, Android | Returns the connection's state and how many messages are waiting, at the moment you ask. |
| `dsx.module.websocket.subscribe()` | `frame`?: string<br/>`id`: string | `id`<br/>`ok` | iOS, Android | Stores one message that is sent first on every connect and reconnect, for example a login or channel-join frame. An empty frame clears it. |

## Action reference

<AccordionGroup>
<Accordion title="ack">

Confirms that one received message was handled, so it is not delivered again.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `id` | string | The name you give this connection; use the same name in every later call. |
| `message_id` | string | The id of the received message to confirm, taken from the message event. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.websocket.ack({ id: "feed", message_id: "feed:7" })
```

```json Result
{
  "id": "feed",
  "message_id": "feed:7",
  "ok": true
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `id` | string | The name of the connection the call applied to. |
| `message_id` | string | The id of the message that was confirmed. |
| `ok` | boolean | True when the call was accepted. |

**Errors**

| Code | Message |
| :-- | :-- |
| `missing_param` | ack needs both an id and a message_id. |
| `not_found` | There is no open connection with that id. |

</Accordion>
<Accordion title="connect">

Opens a named connection to a ws:// or wss:// address, or updates it if it is already open, and reconnects automatically if it drops.

**Arguments**

| Field | Type | Description |
| :-- | :-- | :-- |
| `headers`? | object | Extra headers to send when connecting. The web version ignores them, because browsers do not allow it. |
| `id` | string | The name you give this connection; use the same name in every later call. |
| `protocols`? | string | The WebSocket subprotocols to offer to the server. |
| `reconnect`? | boolean | Set to false to turn off automatic reconnecting. It is on by default. |
| `url` | string | The server address, starting with ws:// or wss://. |

**Example** (from the package's own test)

```javascript
const result = await window.dsx.module.websocket.connect({ id: "feed", url: "wss://example.com/socket" })
```

```json Result
{
  "id": "feed",
  "ok": true
}
```

**Result**

| Field | Type | Description |
| :-- | :-- | :-- |
| `id` | string | The name of the connection the call applied to. |
| `ok` | boolean | True when the call was accepted. |

**Errors**

| Code | Message |
| :-- | :-- |
| `invalid_param` | A WebSocket url must be ws:// or wss://. |
| `missing_param` | connect needs both an id and a url. |

</Accordion>

## Broadcasts

Listen with `window.dsx.module.websocket.on('<broadcast>', (data) => { ... })`. It returns a function that stops listening.

| Broadcast | When it fires |
| :-- | :-- |
| `event` | Sent for everything that happens on a connection: it connects, opens, receives a message, waits to reconnect, closes, fails or drops messages. Check the type field to tell them apart. |

For apps built on Despia V3, see [Migrate from Despia V3](/packages/migrate-from-v3).
